# 周维护的业务审阅

本文件说明周维护需要哪些业务输入与判断。任务计划、授权和验收依
[GOVERNANCE](GOVERNANCE.md)，验证依 [QUALITY](QUALITY.md)，交付和续作依
[DELIVERY](DELIVERY.md)。下面是结果依赖，不是逐步骤启动审批。

## 输入和范围

现有 MTGO 采集仍按每日 09:00 UTC 运行；不因周维护新增定时任务。
成功保留的赛事是已有输入，不重新抓取来证明一次审阅。每个赛制分别确定最早
待审的已结束自然周、已公开周和已接纳赛事。目录增长、日期、Issue 关闭或
周维护完成标记都不能代替赛事接纳。

Owner 指定的同赛制 Melee 赛事，在来源完整、分类可复现、可用牌表可审阅时可以
补充审阅，不要求已经公开。来源、赛事、统计、公开状态和完成记录均与 MTGO 分开。
缺失牌表标为 unavailable；没有规则命中的可用牌表才是 Unknown。

缺失预期赛事或异常来源需要诊断和必要修复，按当前任务范围连续处理；不因为
技术修复另开授权阶段，也不把未知来源当作已完整取得。

## 完整分类审阅

Codex 同时提供完整分类表和机器优先提示。完整 MTGO 表包含本周每场官方赛事的
全部已公布记录，最多到第 32 名；机器没有提示的行不代表分类一定正确。
Melee 补充表包含每个可用分类，Unavailable 另列。主表提供中文名称和准确定位，
不批量塞入全部牌张；需要调查的行再展开主牌、备牌、规则和同类构筑。

Owner 决定类别、子类、名称和允许的 intentional Unknown；Codex 负责查明牌表和
实现决定。`configs/mtgo_intentional_unknowns.yaml` 的既定业务含义不变：仅接受
明确记录的 random_card_pile，不以陈旧、单例、证据少或缺规则作为豁免原因。

规则维护优先简化已有条件。确需新父类或替代分支时，说明现有身份或单个分支为何
不能表达已确认构筑；数量条件取能成立的较低阈值。要求四张而非较低数量时，须有
低阈值导致身份迁移、冲突或分类丢失的具体证据。

类别内容变化按 QUALITY 的 R3 比较同一批完整同赛制 MTGO／Melee 保留牌表，
核对全部已批准迁移及未解释的分类、子类、匹配、冲突和状态变化。有效结果复用；
纯名称变化只检查名称和消费者，不机械重跑分类器。

```text
python tools/compare_classifier_impact.py --format <format> --accepted-rules <accepted.yaml> --candidate-rules <candidate.yaml> --expected-changes <accepted-changes.json>
python tools/export_weekly_classification_review.py mtgo --week <week> --format <format> --output <review.json>
python tools/export_weekly_classification_review.py melee --format <format> --event-id <event> --output <review.json>
```

这些命令生成或比较当前审阅对象，不能代替业务判断。私有诊断、首次名称建议和
含未接纳赛事的审阅材料留在批准的私有位置，不进入公开产品或公共 Actions 附件。
日常工作流的周审交接只上传加密附件，可读材料按 DELIVERY 单独存入现有私有归档；
Codex 从该运行摘要定位并取用，不要求 Owner 手工下载、解密或维护新的记录。
表格导入须核对完整行与实际用户选择；不能把缺值、过期表格或建议值当作验收。

## 数据、Landing 和完成是三个不同结果

完整分类验收后，`data_admissions` 记录批准的明确赛事集合，允许依当前任务发布
该赛制的数据产品。保持连续自然周与空周观察含义；后来到达但未列出的 ID 仍待接纳。
初次公开与历史公开迁移使用各自既定类型，不补造历史人工验收。

分类变化使派生结果过期时更新对应结果；不变的输入、分类结论和其他赛制成果复用。
必要时在一个候选中组合多个已确认赛制，但不能扩大其各自接纳范围。

Landing 从已确定的数据筛选。只有新增、缺失、改变或需业务选择的代表牌、颜色和
显示元数据才交 Owner 判断；已确认结果不因技术步骤变化失效。中文原文、英文内容
及最终周内容预览按当前计划中的业务验收点处理。技术可用性由 Codex 在提交验收前
确认，不能让 Owner 代查图片缺失、控件失效或明显错误数字。

新数据公开不会自动替换旧的已验收 Landing；跨周消费者保护和独立内容接纳继续成立。
只有约定的业务内容、数据交付和内容交付实际完成后，才记录该赛制周维护完成。
旧记录保持 Top-8-only 含义，新记录使用 full_official_classification_v2，绑定已审
赛事、分类主体、完整审阅摘要和 Landing 内容，不成为每行数据库或授权令牌。

Readiness、Issue 和完成记录说明现有事实。相同诊断不重复通知；新诊断更新同一
业务对象的说明，不强制重新打开已经完成且仍有效的审阅。技术查询失败只恢复查询，
不能使全部产品证明失效。当前任务结束不产生永久维护、自动监控或新赛事处理权限。
