# 质量与有限验证

采用 C 模式：本次交付结果检查、受改核心机制测试、少量保障开发效率的检查。
普通任务不默认运行回归套件。本次承诺结果仍须成立；被触发的必要检查失败或未完成时不能交付。
任务授权与故障处理见 [GOVERNANCE.md](GOVERNANCE.md)。

## 阻断资格

检查须能解释：发现什么具体错误及损失、独立正确答案来自哪里、如何容纳合法变化、
什么实际变化触发它且覆盖哪个对象、连同运行及维护成本是否值得。已有、很快、
覆盖率高、冻结当前输出均不是充分理由。没有事故历史也可用具体高损失反例证明价值。

首次实现或实质修改检查，就近证明正确对象通过、相关错误被发现、相关合法变化不误报。
不要求固定测试数、全面变异测试或每 PR 表单。测试自身错误可以修正；必要产品要求仍需有效证明。
修正预期必须依据规范、独立输入或已确认业务变化，不能让生成器同时提供答案和判定。

## 有限范围

| 目的 | 实际触发 | 最小有效证明 |
| --- | --- | --- |
| R1 页面与使用路径 | UI、资源绑定、消费者数据形状或新入口改变 | 操作实际受影响页面，验证内容、反馈、资源解码及合法空状态。共享同构项结合低成本完整性核对与不同分支代表渲染 |
| R2 输入与派生含义 | 数据更新、新接入或生成逻辑改变 | 批准纳入／排除、独立计数和代表性复算，以及实际消费者能读到必要字段 |
| R3 分类内容 | 规则内容或名称改变 | 受影响赛制同输入全量漂移与已批准迁移；有效已有结果复用。纯显示名只查名称及消费者，不自动跑分类引擎或漂移 |
| R4 文档含义 | 治理、规范或设计实质变化 | Codex 对照已确认目标聚焦语义审阅及必要情境；不增加 Owner 审批、固定措辞测试或全仓审计 |
| K1 统计／转换机制 | 筛选、分组、分母、缺失处理、归一化实现改变 | 人工可算小输入覆盖受影响语义与调用；普通数据更新不触发机制套件 |
| K2 分类执行机制 | 匹配、优先级、冲突、Unknown、加载或共享执行改变 | 独立小规则／牌表证明必要语义，按实际影响结合 R3；单条规则内容不是引擎变化 |
| K3 输入、公开与数据契约 | 来源隔离、范围筛选、可见性、打包或读写契约改变 | 获准与排除对象、合法首次／空状态、真实消费者；结构正确不单独证明统计或资源正确 |
| K4 发布与恢复机制 | 包保存／选择／部署／恢复／协调实现改变 | 指定包、损坏拒绝、无重新生成、并发与续作等受改分支；普通发布不重演故障 |
| G1 状态精简 | STATUS 修改 | 120 个非空行／6,000 字符仅提醒。必要信息合法增长不阻断，不删事实或请求 Owner 数值例外 |
| G2 必要入口 | 必要链接或支持命令移动、删除、修改 | 直接目标存在且可定位；不递归历史或外网、不运行有副作用命令来检查存在 |
| G3 选择与续作 | 检查执行器或复用机制修改 | 必要检查确实执行、失败不放行、有效复用与失效拒绝、合法无须检查、查询重试不重做产品检查 |

检查选择和具体命令由 `python tools/project.py check --help` 及入口中的有限映射维护，
不另维护第二份逐文件触发矩阵。工具执行范围选择，Codex 判断实际语义影响；
不建设通用依赖图或证明每次跳过的台账。人工语义审阅、实际浏览器操作也是有效方法，
须如实说明对象、行为和结论，不伪装成自动测试运行。

## 如何取得和复用证明

仅当检查有资格、被实际影响触发、且缺少有效证明时执行。未触发、复用和本次运行通过分开报告。
普通任务可以没有适用自动检查；预期必须执行却选中零项则不算成功。
相关输入、实现、依赖、环境或组合改变才可能使原结论失效，SHA、工作区、PR、日期单独变化不使其失效。
自动工具无法判断语义适用性时，Codex 聚焦核对；影响不明不默认通过，也不默认全量测试。

新数据不重测未改机制。规则变化复用输入资格，只补 R3 和受影响派生结果。
只查 GitHub 状态失败时只续查，不重新取得产品绿灯。正确失败阻止交付，技术修复仍在原授权内。
未知原因如实标注，禁止将故障次数当产品缺陷数。

## 数字、资源与独立预期

占比合计前先确认集合完整、互斥、同一分母；Top N 或过滤子集不强求 1。
优先核对原始计数和未舍入比例，再考虑显示舍入；33.3% 的三项不强求显示 100%。
Unknown、不可用牌表、缺失、无比赛及零胜率依业务规范区分。
图片字段存在或 HTTP 成功不等于解码显示；颜色缺失不等于无色。
滚动窗口、批准新输入、首次状态按其含义判断，不冻结旧数字。

小样例不复制整个当前产品快照，也不能把实际接口全部替换为永远成功的替身。
未解释差异不靠刷新 golden 消失。不同受影响分支需各自有效覆盖，但同一证明不重复取得。
检查维护成本高或反复误报时，只重审该方法和受影响风险，不启动全仓治理巡检。
