# 日常采集与周维护生成解耦（2026-10-25）

Owner 已同意：行为分析暂缓；日常仅保存输入，完整分类材料按周维护或明确诊断准备，公开产品在分类确认和明确接纳后生成。以下是本地实现与验证；未推送、未合并、未触发线上任务，暂停发布继续有效。

## 实际改动

- `update.yml` 保持每日 09:00 UTC 与手动入口，改为 fetch → retain → 轻量清单。移除日常 build 和 Pages dispatch。手动触发该工作流同样只采集入库。
- `integrate_mtgo_collection.py` 只允许已登记范围中的原始赛事、对局、discovery 和 fetched 台账。复用原来源／增量校验；增加旧台账和来源链接不得丢失的集合检查。禁止删除、符号链接、公开产品及规则写入。
- 输入校验可明确不要求公开产品存在；`validate_production_candidate` 的原公开校验默认仍要求完整产品，未放宽发布条件。新卡未识别、规则待审与没有统计文件均不会因此阻止合法输入入库。
- 成功候选以 gzip + CMS 加密补丁交接，保留 30 天；gzip 同时解决 OpenSSL 无法串流封装空补丁的问题。接收端解密后验证原补丁、来源及报告摘要，再按当前 master 精确应用。无关改动保留；冲突不猜测合并、不重采；已完成提交按运行标识和补丁摘要复用，空补丁不制造提交。
- 原七天 checkpoint 保留；失败兜底移动到交接之后，因此校验、加密或上传失败也有机会保全已采集输入。超过临时保留期限仍须沿现有 DELIVERY 主动保存活动候选，不能承诺 Actions 附件永久存在。
- `generate_mtgo_collection_readiness.py` 增加私有 schema 1.9.0 清单：来源数量、已结束且含未列入接纳登记赛事的周次、discovered／deferred 来源。旧 1.6—1.8 文档兼容性保留。每日清单不执行分类，不验证人工接纳、不推断周完成、不宣称来源齐全。单一轻量通知按摘要去重，不替换、关闭或重开完整周审通知。

## 周维护和修复入口

完整分类仍使用 `tools/build_weekly_review_web.py --scope <format>=<week>`；原完整 readiness 诊断工具保留，退出日常热路径。取得对应分类确认与赛事接纳后，使用既有：

```text
python -m mtgmeta.mtgo --root <candidate> --format <format> publication stage
```

需要时通过 `--co-stage-format` 合并已接纳赛制；已有阶段缓存、失败续作、确定性检查和本地应用方式不变。默认保留 Landing，新增内容仍独立验收。没有另建固定周生成任务、通用调度器或审批流程。
