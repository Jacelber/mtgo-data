## 已实施的加载变化

- Melee overview 1.2.0 在每个 scope 提供 `literal_record`。分母来自该 scope 的全部 `win_rate_included` 参赛者视角，包括缺失牌表的参赛者；DQ 对局的双方仍排除。不能直接用 `result_counts` 或已知类别之和替代。正常概况不再读取完整 `decks.json`，第一次展开构筑详情时才加载。
- 保留旧版 overview 的牌表回退。新 1.2.0 缺总体战绩会明确失败，不能伪造零战绩。公开 schema 继续接受原 1.0／1.1，当前产物检查会将旧契约标为可重建。
- 当前视图通过引用计数保留自己的 JSON 资源。16 MiB／24 项仍是非活动资源的原有 LRU 预算；当前视图的必要资源可超过该预算。新视图先取得资源，再释放旧视图；失败／过期请求释放临时引用。这样 scope／筛选切换不会先把自己需要的大矩阵淘汰。刷新继续整组暂存、校验和提交。
- 此能力接入 MTGO Landing、统计、对局、八强及 Tabletop 单／多赛事。离开视图解除保留，未扩大为所有浏览历史常驻。英文视图不请求中文卡牌 lookup；中文继续使用原有缺失回退。

## 矩阵契约与兼容

Melee matchup 1.1.0 显式声明 `matrix_encoding: "sparse-zero-v1"`。生成器仍先构建并核对完整矩阵，再在输出时省略 W／L／D 全为零的格子；保留全部行、identity、顺序和 overall。非零格子的战绩、literal record、旧兼容率、区间和 mirror 字段原样保留。

该版本内，被省略的已知列表示零战绩，胜率及区间为 null，对角格仍有 mirror 含义。空行必须保留。旧 1.0 的缺格不能套用这一解释。Python 和 JavaScript 多赛事聚合显式识别两种版本，继续验证身份域、反向格、镜像和对局守恒；不放宽原有跨版本／分类摘要兼容检查。

只调整实际发现大体积的 Melee 输出，不重写 MTGO 的矩阵格式。零值省略后收益已足够，本轮不再引入分片请求、索引和额外合并路径。
