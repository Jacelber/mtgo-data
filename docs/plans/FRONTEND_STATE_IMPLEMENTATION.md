## 已复现的问题

在实际页面、当前公开数据和修复前脚本上，通过控制响应顺序复现了三项具体错误：

1. 从 Modern 切到 Pioneer，再切到 Standard；Pioneer 名称请求最后返回，覆盖正在使用的 Standard 名称契约。
2. Standard 区间数据返回 503 时，导航与 URL 已选择 Standard，正文仍保留 Modern 构成图，只在旧内容上插入错误提示。
3. 四周统计请求延迟，用户经历史导航回到一周；迟到请求仍把 `currentContext` 写成四周，虽然最终 HTML 因渲染序号检查没有覆盖。

证据保存在 `/workspace/scratch/frontend-roundc/before.log`、`before-history.log`，修复前脚本保存在同目录 `baseline/`。第三项使用相同赛制的不同区间，避免缺失异赛制名称提前抛错而掩盖上下文覆盖。

## 实现

每次渲染复制并冻结请求目标，包括赛制、产品路径、区间、周次、赛事选择、范围、语言以及所需详情。集合转为独立的冻结数组。所有加载参数取自此目标，异步返回后通过请求有效性检查，才进入同步的名称绑定、状态规范化、上下文与 HTML 创建部分。纸牌赛事的第二段多赛事加载也使用该目标和对应名称契约。

名称加载只填充对应赛制缓存，不直接改当前名称。过期结果可以留下可复用的资源缓存，但不能改当前页面状态、名称、HTML、URL、错误提示或焦点恢复。两个延迟布局／焦点回调也检查渲染序号。

页面记录已成功显示对象的身份，包含赛制、产品、区间／周次／赛事集合、纸牌范围、语言，以及适用的排序／过滤状态。切换对象立即清除旧上下文并展示加载状态；失败展示目标错误态和重试。URL 在开始请求时同步目标，成功后仅替换规范化的选择，不另增加历史项。同一对象首次打开详情失败时，保留对应列表并提供就地错误与重试。

后台刷新只从已显示且没有前台加载的对象启动。结果和“应用更新”动作均核对对象及渲染序号，旧更新／旧错误不能出现在新页面；同一对象的正常更新仍先提示，点击后应用。导航同步清除旧刷新提示、旧“已加载”状态和矩阵浮层。

通用构成图的中英文文案改为“所选区间”，Landing 专属“本周”含义保持。对局格保留原来的置信区间半宽显示，另在悬浮、点按、键盘聚焦及可访问标签中展示真实上下界；没有把 Wilson 区间假定为以胜率为中心的对称区间，也没有修改公式。浮层适配屏幕宽度，滚动、失焦、点击其他对象或导航时关闭。
