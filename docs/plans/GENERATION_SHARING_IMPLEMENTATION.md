## 生成效率

同一场赛事的 statistics、matchup、publication 生产序列原先构建统计四次、加载规则四次。发布函数内部生成矩阵时再次调用完整统计入口，生成阶段也没有复用刚算出的统计。

新增 `build_event_matchup_from_statistics`，复用当前操作中已验证的统计，重新读取并核对 ledger 的实际 SHA-256 后构建矩阵。`_generate_melee` 仅在本次 statistics producer 确实执行时复用其结果；若断点跳过该 producer，矩阵仍通过原 from_paths 入口重建和验证。没有增加跨赛事／跨进程缓存，也不信任未经检查的旧输出。

发布阶段仍独立从保留输入重建统计，复用这次统计计算矩阵；随后 `_verified_outputs` 对实际公开文件逐字节核对，继续绑定实际文件描述符。原 GenerationProgress 的代码／输入／输出摘要及最终验证保持，损坏输出会重建，相关代码变化会使旧 checkpoint 失效。

对最大赛事 Modern 405588，在相同输入上以 cProfile 测量完整三个生产动作：统计和规则加载均从 4 次降到 2 次；单次运行 54.85 秒降到 31.27 秒。overview、decks、quality、matchup、meta、catalog 六份序列化结果摘要全部相同。这是带 profiler 的同机单次观测，不能当作所有赛事或生产环境的耗时保证；调用次数和结果等价有直接证据。保留发布独立重建，避免为消除最后一次重复而扩大缓存及可信边界。

## 可见变化

- 两个产品入口加入“复制当前视图链接 / Copy view link”。链接保存实际视图状态，不用面向搜索引擎的精简 canonical URL 代替。复制失败时展示选中的只读链接，方便手工复制；加载中或失败状态不可误分享为成功页面。
- 补齐主流筛选、自选套牌、矩阵行／列展开、统计／实体赛子类展开和详情参考模式的 URL 保存与恢复。已有赛制、产品、语言、区间、排序、周次、赛事集合、scope、详情与特选定位继续复用。菜单草稿、悬浮和临时焦点不进入 URL。格式错误、重复及当前数据不存在的相关身份规范化处理，浏览器前进／返回也恢复相应状态。
- 矩阵结果格采用一个 Tab 停留点，方向键在行列移动并跳过无数据格，Home／End 到本行首尾；行列展开按钮和详情链接保留原有键盘访问。Esc 关闭战绩提示。
- 筛选菜单 Esc 放弃未应用草稿，返回入口；详情 Esc 关闭对应详情并恢复入口，包括 Landing、统计、八强和实体赛。卡图弹窗优先处理自己的键盘状态。
- C/D 已完成的状态一致性、完整区间提示、刷新同步和按需加载一并进入此候选，未重复改写统计含义。

## 验证及证据

35 项相关 Python 测试通过，覆盖复用与独立重建路径、ledger 变化拒绝、输出损坏拒绝、checkpoint 复用／失效、缺牌表与原有多赛事契约。50 项相关 JavaScript 测试通过。

浏览器有效结果覆盖 40 个用例：原 C/D 的 29 项及新增分享／键盘的 11 项。组合运行中新增多赛事用例在与完整打包并行时耗尽 30 秒；trace 显示事件切换单步耗时约 18 秒。保持原超时及断言，分离打包后整组 11 项在 37.6 秒内通过。Landing 测试原先同时匹配展开与关闭按钮，改为准确定位展开按钮，保留“恢复展开”的要求，并补充 Esc 关闭及焦点断言。其余 29 项验证仍适用，没有反复重跑无关路径。
