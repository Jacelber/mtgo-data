## 1. 旧内容使用原接纳范围

根因：新内容准备与旧内容读取共用的helper都要求当前交付周等于内容周，导致数据推进W40时，未变的W39内容提前被拒绝。

- 新内容准备继续核对当前第4步交付范围；未接纳赛事不进入内容材料。
- 旧内容读取显式传入已保存的`admitted_scope`。既有接纳解析器只恢复截至该内容周的接纳记录，照常核对来源清单；所得周次与范围摘要必须等于原记录。
- 旧内容路径不读取当前最新publication metadata来重绑自己。摘要不符、输入改变或原记录不可定位仍失败；不修改旧receipt，不补造接受，不要求用户重验。
- 生产数据的默认接纳解析不变；按周恢复仅供已绑定内容读取使用。

可运行验证：[test_weekly_cross_week_and_faces.py](../../../tests/test_weekly_cross_week_and_faces.py)。测试使用隔离复制的Pauper保留输入及配置，页面和内容决定均为合成测试对象：

1. 用原facts和原内容导入器建立W39内容，先经过`content_packet()`和`resume_summary()`确认读取成立。
2. 构造一个可分类的W40测试赛事，经完整分类材料和既有`acceptance_record()`新增接纳；只将测试时钟设为2026-10-06，交付元信息推进W40。保留W39 Landing与内容文件。
3. 再调用实际`content_packet()`和`resume_summary()`：原内容仍适用，状态为`accepted_recorded`，没有`content_problem`，内容文件字节未变。
4. 隔离fixture另有一个未接纳的晚到W39输入；它与新W40赛事均不混入原内容范围，晚到输入也不因W40接纳而获得授权。
5. 错周或伪改范围摘要、真实中文修改均拒绝；受保护的旧赛事牌表修改被来源绑定拦截，续作状态相应为`needs_repair`。首次新内容的当前交付限制仍保留。

修复前，本测试走到W40后读取W39时复现`Content requires the delivered admission scope for this week`；没有mock范围helper、内容读取或续作函数。这里验证的是接纳/交付元信息推进后的读取合同，没有模拟一次真实生产部署，也没有重跑整批数据发布。

## 2. 补图使用完整的既有牌面解析

根因：新入口自行按牌面名字找index，完整“Front // Back”不能命中任何单面名，随后误用没有图片的顶层对象。

现在直接对有限牌张响应调用既有`_bulk_lookup()`及其名称规范化，沿用其顶层、单面和首个有效牌面的选择规则，使用返回的`face_index`建立缓存路径。用户选择的名称保持不变。未受影响的缓存与下载验证逻辑不变。

同一测试文件中的6个参数情境覆盖：

| 输入 | 有效图片响应 | 真正缺图，修正后续作 | 错误牌张响应，修正后续作 |
| --- | --- | --- | --- |
| 单独正面名 | 通过 | 先明确失败，再通过 | 先明确失败，再通过 |
| 完整双面名 | 通过，选首个有效牌面 | 先明确失败，再通过 | 先明确失败，再通过 |

每个情境都核对原页面选择不变、已有缓存字节不变、只补1张目标图；再调用时下载0张。使用有限本地响应，禁止真实网络。修复前完整名称的三条路径均复现`No normal image for selected Feature card Front // Back`。
