## Purpose and boundary

P9-08 closes the remaining consumer genericity gap exposed by the approved
Standard source pilots. The Tabletop consumer previously loaded format metadata
but still presented fixed Modern scope labels and Modern-specific explanatory
copy. This task makes those labels derive from the selected event's validated
format and the existing language dictionary.

The task changes only the static Tabletop consumer, its bilingual dictionary,
focused tests, and Phase 9 closeout documentation. It does not add a Standard
event to the production catalog, edit `configs/melee_events.yaml`, retain live
source responses, generate statistics, alter a public Schema or statistical
formula, change a workflow, dispatch production, or implement Phase 11
multi-event aggregation.

## Format consistency boundary

`P8TabletopController.loadEvent` now resolves one event format only after
checking that all loaded documents agree:

- event catalog;
- event metadata;
- overview;
- matchup;
- quality;
- Tabletop deck document;
- MTGO comparison deck document.

The resolved value must also match the requested format. A missing or
inconsistent value is rejected instead of allowing a mixed-format consumer
state.

The renderer passes that validated format into scope labels and
format-sensitive quality notices. The language dictionary remains the single
source of the user-facing format name.

## Regression evidence

The current production event `434455` was served from the isolated workspace
and reviewed in the in-app browser:

- Chinese scope labels remained `第一日摩登`, `第二日摩登`, and
  `全部摩登瑞士轮`;
- English scope labels remained `Day 1 Modern`, `Day 2 Modern`, and
  `All Modern Swiss Rounds`;
- switching to Day 1 kept the selected scope across the language change;
- the mixed Day 2 selection-bias notice used the selected format;
- Event Overview and Matchup Win Rates both rendered;
- the browser console contained no errors.

Standard Tabletop production activation is outside P9-08. Its exact Chinese
and English scope labels are therefore verified through the executable
dictionary contract rather than by adding a synthetic or unapproved production
event.
