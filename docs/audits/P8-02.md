## Revised acceptance boundary

The first P8-02 draft proved the format-first information architecture but did
not faithfully preserve the current production feature surface. Owner review
therefore rejected that draft as a sufficient UI baseline and established
these mandatory constraints:

1. Chinese is the default prototype language. English is used only for
   established names without an approved Chinese equivalent.
2. Chinese copy must be accepted before proposed English copy is reviewed.
   The language control remains visible, while the English copy pass is
   intentionally deferred rather than silently treated as approved.
3. The prototype must contain at least every current production feature and
   explanatory element. No current feature or wording may be deleted without
   explicit owner review and acceptance.
4. Apart from the already approved format-first, subtype, completeness,
   weekly-Top-8, and Tabletop Major Events requirements, the prototype must not
   add a production feature or product copy without owner review.
5. Superdesign remains outside the task. It was not used.

The revised prototype is limited to:

- `docs/prototypes/P8-02/index.html`;
- `docs/prototypes/P8-02/styles.css`;
- `docs/prototypes/P8-02/app.js`;
- this audit;
- the P8-02 state in `docs/STATUS.yaml`.

This list records the paths delivered by P8-02. P8-08 later relocated the
reusable stylesheet to `assets/css/phase8-base.css` and updated the P8-02 entry
to preserve the historical review URL.

No production HTML, JavaScript, CSS, generator, Schema, test, workflow, or
generated data changed.

## Approved Phase 8 additions represented

### Format and product navigation

- Format is the first selector.
- The five product controls always remain visible.
- A format with no available product remains visible and gray.
- An unavailable product remains visible and gray.
- Hover/focus uses the approved wording `暂未上线，正在开发中`.
- Clicking an unavailable format or product shows the same status without
  navigating.
- A format switch retains the current product when available; otherwise it
  selects the first available product from left to right.
- The MTGO-specific controls are labeled `MTGO官方数据统计`,
  `MTGO对阵胜率`, and `MTGO八强牌表`.

### Parent and subtype behavior

- Parent archetypes are the default.
- Parents with at least two maintained subtypes expose only a plus/minus
  control; there is no redundant `subtypes` label.
- Expanding a parent retains its archetype row or column and inserts full,
  self-contained subtype rows or columns beneath it.
- Matchup rows and columns remain independently expandable.
- Archetype text stays aligned whether or not a plus/minus control exists; the
  control hangs to the left, while subtype labels use a small additional
  indent.
- Parents with zero or one subtype expose no expansion control.
- A parent with maintained subtypes opens no synthetic parent-average deck
  detail; the user must select a subtype.
- Construction detail uses the selected subtype as the comparison identity.

### Completeness presentation

The official-statistics example names:

- the measured object: high-score decklists;
- observed usable decklists;
- theoretical expected decklists;
- the resulting percentage.

The matchup example names:

- the measured object: Videre event archives;
- expected events;
- events with usable archives;
- deferred and missing events;
- the resulting percentage.

Both values are explicitly marked as prototype examples. They are not
statistical definitions or generated results. P8-04 must still define the
formula and unavailable states; P8-06 must generate the production payload.

### Weekly MTGO Top 8

- One native week dropdown is used at every screen size.
- The selected week displays one comparison table with rank as the first column
  and one column per event.
- Each event header contains its approved abbreviation, date, and player count;
  the full event name remains available as hover text.
- The table displays all eight ranks and a full subtype name in every event
  cell.
- Selecting a subtype cell opens one shared construction-detail component below
  the table.
- The left column becomes the exact selected event deck instead of the best
  deck.
- Deviation and the comparison column use the applicable subtype base.

The prototype contains exactly 3 event columns and 24 ranked deck cells.
P8-05 remains responsible for the complete generated event/week product.

### Tabletop Major Events

The product now places Event Overview and Matchup above event selection:

- Event Overview uses one event dropdown.
- Matchup uses a compact scrollable checkbox pane and preserves prior
  multi-event selections.
- Entering Matchup includes the current overview event; returning to Event
  Overview opens the newest selected event.
- The approved mixed event `434455` and two clearly labeled fictional events
  exercise `mixed`, `constructed_day2`, and `constructed_single_stage`.
- The mixed reference defaults to all Modern Swiss.
- Scope controls expose only the ranges supported by every selected event.
- Event Overview begins with a non-expandable overall comparison row.
- Scope- and structure-specific columns prevent mixed Day 2 qualification from
  being presented as pure Modern conversion.
- Mixed all-Constructed scope exposes no combined high-score value.
- Visible `胜率` is the literal share of valid matches won:
  `W / (W + L + D)`. Normal played draws remain in the denominator and do not
  count as wins. Intentional draws and the existing non-play exclusions remain
  excluded.
- The primary overview and `整体` values include mirror matches. P8-04 must
  retain an explicit non-mirror value as supporting output rather than using it
  as the only or primary visible rate.
- Matchup-matrix diagonal cells display the real mirror W-L-D rate instead of
  an unavailable dash. This preserves the existing MTGO behavior and applies
  the same UI contract to Tabletop, where normal mirror draws may produce a
  value below 50%.
- Metric `i` help contains the owner-reviewed definitions for points, high-score
  measures, conversion, all-match W-L-D records, match count, and completion.
- The parent/subtype overview table and hierarchical matchup matrix remain
  independently reviewable.
- Visible source link, date, event structure, event ID, quality, Unknown,
  disqualification, Draft/playoff exclusion, and selection-bias context remain
  available.
- multi-event Matchup explains that raw W-L-D records are aggregated before a
  rate is calculated.

The fictional event values are prototype-only and never enter production
configuration or statistics. Real multi-event aggregation remains Phase 11.
The product does not merge Melee-derived data into MTGO statistics.

### Real-data review gate

Some final display decisions cannot be settled with representative values.
P8-07 therefore loads representative real generated payloads into the accepted
review UI and requires a second owner acceptance before P8-08. Display-only
findings may amend the UI there. Missing statistical fields return to a
separately authorized backend contract task and are never reconstructed in the
browser.
