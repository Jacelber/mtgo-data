## A．发布从失败处继续

### 问题和改动

旧 preparation 虽然在开始读取了 base，但没有先处理未结束写入，导致本地化、
构建及归档后才被 dispatch 拒绝。现在准备入口先调用共享 preflight，再进入昂贵工作。
已结束任务的远端操作由已有状态转换收敛；仍运行或查询未知时保留原状态。

归档成功后，在现有包记录内保存准备标识和原 base。同一准备标识再次运行时找回
该包，跳过 localization、build、encryption 和 archive，直接进入已有 dispatch 入口。
有可信记录的历史包可用 archived_package / archived_base 显式选取。此关联只用于发现成果，
不代表人工批准、不修改不可变归档包，也不是新增审批台账。

### 已验证的具体行为

| 情境 | 实际结果 |
| --- | --- |
| 旧任务仍在运行 | 返回 waiting，不查询重发、不下载产品、不进入新准备 |
| Pages 返回 updating_pages | 保留同一 pending；下次继续查询同一 Pages ID |
| 原查询暂时失败 | 不清 pending、不制造成功、不发送新操作 |
| 平台和服务均确认 | 记录原操作成功，取得其实际 base |
| 平台已结束但服务不匹配 | 结束写入记录，产品 health 保留 unknown，适用前版保留 |
| 上述页面随后恢复匹配 | 下一次 preflight 继续确认该原操作，health 可收敛为 passed |
| 能证明旧 claimed 任务从未发送 | 清理未发生的写入；不伪造部署 |
| 发送结果未知、不能证明未发送 | 保留未知，拒绝重复写入 |
| candidate 已归档，后续步骤失败 | 同一准备标识能找回相同 package 和原 base |
| base A 已被另一交付推进到 B | 原包保留，拒绝强行发送或改写原 base |
| 查询期间发生外部部署或状态竞争 | 拒绝覆盖变化后的事实 |
| 存在恢复意图或自动发布暂停 | 继续保留；不决定回滚，不自行解除暂停 |

复核了真实 workflow 内嵌入口的 ready / waiting / stale 分支，以及原包路径跳过
昂贵作业的连线。查询作业仅新增 Pages / deployment 只读权限，未扩大线上写权限。
最终 writer 的串行协调和发送前检查继续保留。

本次补修把校验集中到 delivery 的 `archived_preparation`：原 base 只读取已有完整包的
control state preparation 记录，调用者输入只做相等核对；多个记录即使 base 相同，
也必须明确选择记录。prepare-pages、直接 dispatch 和 writer request/claim 均接入。
缺少可信记录的旧包报告待查来源与组合，保留原包，不进入自动复用或重建。

| 本次新增核对 | 结果 |
| --- | --- |
| 记录原 base=A，当前 B，显式填写 B | 拒绝输入与记录不符，不发送 |
| 记录原 base=A，当前 B，显式填写 A | 保留原包，判定组合过期，不发送 |
| 包、具体 preparation、原 base=A 与当前 A 完全匹配 | 复用原包，传递同一 preparation |
| 多个 preparation，未明确选择或选择不属于该包的记录 | 拒绝，不任选一个 base |
| 旧包缺少可信 preparation/base | 拒绝复用，报告来源与组合待查 |

证明：本次 `tests/delivery/test_continuation.py` 的 29 个有限情境全部通过，包含真实
prepare-pages 内嵌入口的显式与自动路径、原有续作情境及直接发送入口的防绕过核对。
首次提交的 dispatch、platform 与 CLI 验证结论保留，本次没有扩大重跑范围。
这些是本地机制与入口验证，没有在生产制造超时或故障。

Owner 验收点：是否接受上述续作方式及并发边界，而无需重新处理技术状态。

## B．辅助候选与业务验收分开

当前事实构建不再读取候选文件，仍计算真实赛事、分类、统计和牌表目录摘要。
Feature 准备入口先核对完整分类验收，再检查候选的赛事、分类、筛选策略、
统计事实和牌表目录；缺失或过期的未决候选自动重建后再次核对。

| 情境 | 实际结果 |
| --- | --- |
| 尚无有效完整分类验收 | Feature 仍不可提交，不提前生成候选 |
| 分类已验收，候选缺失或过期 | 自动重建后提交，不要求额外技术批准 |
| 候选包含人工决定 | 保留旧文件，按现有提交机制处理受影响材料 |
| 当前赛事或分类与验收不同 | 仍阻断；不能通过候选重建隐藏真实变化 |
| 仅旧辅助候选过期或损坏 | 不影响基础 subject 构建，不污染当前事实 |
| 既有 W38 Web 提交快照 | 仍禁止覆盖 |

未修改 submission / acceptance 实现。中文、英文、赛制、未展示维度和最终页面
继续独立绑定；保留旧 Landing 的消费者组合保护未变。

证明：受改 Feature 入口、候选生成保留策略、真实内容变更拒绝和现有 submission
检查通过。同输入对照基线函数，Standard 当前基础事实没有变化；Modern、Pioneer、
Pauper 的基础事实也未变化，且三者真实 W38 content packet 仍通过原有 acceptance。
辅助 candidate_evidence 现在仅由 Feature 入口填入，不再进入基础事实构建。

Owner 验收点：辅助候选可以自动维护，真实业务验收边界仍保持。
