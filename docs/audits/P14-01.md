# P14-01 Pauper taxonomy, rule implementation, and retained-corpus review

Status: Owner-accepted on 2026-08-30; unchanged P14-01 completion through one Ready PR, required CI, and merge is authorized.

## 1. Problem

Pauper had retained MTGO decklists but no repository-native shared taxonomy. The prior Phase 14 wording also did not identify where the implemented rules would receive their final retained-corpus review before private product generation.

## 2. Implemented structure

The classifier is one format-specific rule document consumed by the existing shared engine. Its final local candidate contains 64 parent archetypes, 71 concrete output identities, and 89 deterministic rules.

Three parents define subtypes:

- `ephemerate`: `jeskai`, `four-color`;
- `battle-screech`: `mono-white`, `boros`, `orzhov`;
- `packbeast-swarm`: `boros`, `mardu`, `mono-white-learn`, `mono-white`, `esper`.

Neither parent has an implicit Other or a parent-only fallback. An unsupported build remains `Unknown`.

There is no `gates` parent. `selesnya-gates`, `jeskai-caw-gates`, `snacker-gates`, and `naya-gates` are independent parents. `naya-hawkeye` is also independent and has higher priority because Hawkeye is its primary plan even when the deck uses Basilisk Gate.

`mono-red-rally` and `mono-red-axe` are independent parents. A deck with the complete Rally engine remains Rally even when it also contains Inventor's Axe.

## 5. Evidence-backed preliminary refinement

The initial implementation reproduced the proposal result: 1,916 classified, 1,871 consistent, and no conflicts. Review then found five recurring Grixis Affinity lists across five retained events with the same engine:

- `Cleansing Wildfire >= 3`;
- `Cryogen Relic >= 3`;
- `Refurbished Familiar >= 3`;
- `Utrom Monitor >= 3`;
- `Silverbluff Bridge >= 3`;
- `Drossforge Bridge >= 3`.

That conjunction matched exactly those five Grixis Affinity references and no other deck in the 1,956-deck review corpus. Rule `grixis-affinity-wildfire-monitor` therefore adds the stable branch without broadening the generic Affinity rules. It raises coverage and correct results by five while preserving zero conflicts.

No other mismatch was changed before Owner review. Low-sample labels, the Fusion Gate sample, the eleven unresolved historical Mono-Red records, remaining Unknown records, and classified-but-inconsistent records must be clustered and presented with recommendations before any further rule change or final acceptance.

## 6. Remaining P14-01C Owner-review loop

The pre-review result contains 35 Unknown records and 45 classified-but-inconsistent records. P14-01C is not complete until:

1. both sets are clustered by stable primary-engine and deck similarity;
2. every cluster receives an evidence-backed recommendation: add or adjust a rule, correct the manual reference, preserve intentional Unknown, or defer as a low-sample candidate;
3. representative lists and every affected record are presented to the Owner;
4. the Owner confirms the classification decision for each cluster;
5. only confirmed decisions are applied, the affected focused evidence is rerun, and the final taxonomy is frozen.

The machine replay and the five-list Grixis Affinity branch are preparation evidence, not a substitute for this human review.
