# Card Localization Delivery Architecture Decision — 2026-08-29

Status: `Accepted; completion publication authorized`

## Outcome

Select a **bounded Landing hot set plus controlled direct delivery**:

- package the Chinese complete-card images that are visible on the default MTGO
  Landing page into the generated Pages artifact;
- obtain every other Chinese image only when the user asks for it, from the
  exact Scryfall or MTGCH image URL admitted by the localization manifest; and
- keep the existing English complete-card image as the immediate and failure
  fallback everywhere.

Do not run another Chinese-image sizing trial. The Owner accepts the byte size
of the corresponding English `normal` complete-card images as the planning
proxy for the Chinese Landing hot set. The production candidate still records
and enforces its actual generated bytes because Pages cannot admit an
unbounded artifact; that is ordinary build validation, not a new architecture
trial.

## Exact local-image subject

For each executable format on the current default MTGO Landing page, derive the
hot set only from `stats/<format>/mtgo/landing/current.json`:

1. every `environment.rows[].key_cards[]` representative card; and
2. every `features.items[].featured_cards[]` card displayed in the Feature deck
   four-card groups.

Resolve those names to immutable `oracle_id + scryfall_id + face_index`
identities, then deduplicate by identity. Do not include expanded decklists,
statistics, Top 8, Tabletop, a non-default archived Feature week, or every card
in a format.

The current offline snapshot contains:

| Default Landing subject | Standard | Modern | Combined after cross-format deduplication |
| --- | ---: | ---: | ---: |
| Representative-card occurrences | 14 | 26 | 40 occurrences |
| Unique representative names | 13 | 26 | 38 unique names |
| Feature-card occurrences | 20 | 12 | 32 occurrences |
| Unique Feature names | 19 | 10 | 28 unique names |
| Union of representative and Feature names | 29 | 34 | **61 unique names** |

These counts describe the current default documents; they are not a permanent
file-count constant. Every Landing generation recomputes the exact subject.

## Capacity rule without another Chinese sizing trial

The existing English Cache-B uses Scryfall `normal` complete-card images, a
5-MiB per-image limit, and a 67,108,864-byte generated-overlay ceiling. The
base Pages artifact measured 270,195,353 bytes against a 1,073,741,824-byte
maximum, leaving 803,546,471 bytes before generated overlays.

For the Chinese Landing hot set:

1. resolve the corresponding English `normal` image for every exact hot-set
   identity through the same Scryfall bulk-data build input;
2. sum those English image bytes after identity deduplication and record the
   value as `english_proxy_bytes` in the candidate report;
3. require the proxy total to fit the existing 67,108,864-byte overlay ceiling;
4. build the Chinese hot set from the accepted official/community precedence,
   recording the actual byte count and digest of every retained source image;
5. require the actual Chinese overlay, including manifest and attribution, to
   fit the same 67,108,864-byte ceiling and the complete Pages artifact to fit
   its existing 1-GiB ceiling; and
6. fail the optional Chinese overlay atomically if either limit is exceeded.

Using the English bytes as a proxy supersedes DEC-140's requirement for a
separate pre-decision Chinese byte-distribution trial for this exact bounded
Landing subject. It does not authorize using English bytes to estimate a full
format, all decklists, future products, or a complete six-format mirror. The
withdrawn 256-MiB/1,024-file proposal remains rejected; this design has no
arbitrary 1,024-file allowance.

## Source and packaging rules

At build time:

1. close the catalog-rooted localization subject and resolve every English card
   or face to its immutable identity;
2. resolve names and images independently: Scryfall printing evidence proves
   `official`; otherwise an exact-identity value supplied by MTGCH is
   `community`; otherwise use `english_fallback`;
3. for a hot-set official image, retain the exact original Scryfall byte; for a
   hot-set community image, retain the exact MTGCH-supplied byte under the
   Owner-recorded permission; never convert, crop, recompress, filter, overlay,
   or relabel either class;
4. retain content-addressed Chinese hot-set files plus one manifest containing
   identity, localized name, provenance, attribution, source snapshot, byte
   count, digest, local path where present, and exact validated source/fallback
   URLs;
5. keep raw upstream responses and images outside the admitted subject out of
   Git, Pages, and workflow artifacts; and
6. publish the Chinese overlay atomically or omit it and preserve the English
   site. Never publish a partial or identity-ambiguous hot set.

The generated hot set may be retained as a subject-addressed workflow artifact
for the same bounded reuse model as English Cache-B. Chinese image bytes remain
outside Git history and enter Pages only through the verified generated-overlay
boundary.

## Browser behavior

1. Load the optional localization manifest. A missing or rejected manifest
   leaves the English product unchanged.
2. For a default-Landing hot-set card, use the local Chinese image immediately.
   If that local entry is missing or rejected, use the existing local English
   Cache-B or English image path.
3. For every image outside the hot set, request only the exact official
   Scryfall or community MTGCH URL admitted by the manifest, and only when the
   card is visible or the user invokes hover, keyboard focus, touch, click, or
   preview behavior.
4. Route external starts through the existing paced one-active-request,
   timeout-bounded, retry-bounded controller. Replace English only after a
   Chinese image decodes. Any cancellation or failure leaves or restores
   English.
5. Do not call MTGCH search, result, set, card-description, or metadata APIs in
   the browser. Do not construct an upstream URL or prefetch a format's full
   population.
6. Use normal browser HTTP/image caching only. Add no service worker,
   persistent application image store, proxy, or full Pages mirror.

MTGCH therefore remains optional: all default Landing Chinese images are local
when the optional overlay was admitted, while a source failure elsewhere can
affect only the requested Chinese enhancement and cannot remove the English
card or page.

## Existing-image cleanup boundary

The current representative-card table still maps key cards through tracked
`assets/images/representative-cards/` files, while Feature cards use the
generated English Cache-B or Scryfall fallback. The new hot-set subject must
replace both display branches through one identity-based selector.

During the consumer task, inventory every caller of the tracked representative
assets and duplicate complete-card selection logic. Remove only branches and
files proved to have no caller after the shared Chinese/English hot-set path is
validated on current, archived, and legacy routes. Keep English Cache-B as the
local fallback; do not delete a legacy route or English image merely because a
Chinese hot set exists.

## Required implementation sequence

### 1. `L10N-B1 — real mixed-delivery candidate`

Problem: the synthetic localization builder models a closed local-image bundle,
while production needs a precisely bounded local subset plus direct URLs.

Operations:

- define the current-default Landing hot-set extractor from representative and
  Feature cards and prove the current 61-name subject with deterministic local
  fixtures;
- evolve the localization Schema and builder so each record can declare local
  hot-set, direct official, direct community, or English fallback delivery;
- resolve the corresponding English full-card image bytes and record the
  deduplicated proxy total;
- build the real candidate into a repository-external directory using exact
  official/community image bytes only for the hot set and exact URLs for every
  other resolved identity;
- enforce identity, permission, attribution, host, digest, 5-MiB per-file,
  64-MiB proxy, 64-MiB actual-overlay, cleanup, and atomic-failure rules; and
- change no Pages path, workflow, or browser consumer.

Effect: one external candidate proves the complete localization manifest and
the bounded Landing image package without a separate Chinese sizing trial.

### 2. `L10N-B2 — optional Pages overlay admission`

Problem: an external candidate is not yet safe to reuse or publish.

Operations:

- add a subject digest that binds catalog inputs, default Landing hot-set
  inputs, source snapshots, manifest, and every retained image digest;
- admit a separate generated localization overlay under
  `assets/card-localization/v1/`, capped at 67,108,864 actual bytes and the
  existing 1-GiB complete Pages ceiling;
- reuse only an exact trusted subject-addressed artifact; otherwise build into
  temporary storage and verify before packaging;
- retain only the verified hot-set bundle for bounded workflow reuse and never
  retain raw responses or non-hot-set image bytes; and
- prove that missing, rejected, oversized, or failed localization output omits
  the optional overlay and leaves the English Pages artifact valid. Add no
  Chinese browser consumer.

Effect: Pages contains only the current default Landing Chinese hot set and its
manifest, not all cards from every product or format.

### 3. `L10N-C — shared consumer and image-code cleanup`

Problem: Chinese views still do not use the admitted overlay, and Landing has
separate representative-art and Feature full-card selection paths.

Operations:

- add one immutable-identity localization resolver for applicable MTGO and
  Tabletop views;
- make default Landing representative and Feature cards use local Chinese
  hot-set entries, with local English Cache-B or the existing English path as
  immediate fallback;
- make non-hot-set cards use exact admitted URLs through the shared paced
  controller and preserve English on every failure;
- expose truthful official/community/fallback labels and attribution;
- validate desktop, 390-pixel, 412-pixel, hover, keyboard focus, touch, click,
  cancellation, timeout, failed decode, missing/rejected overlay, archived
  Feature week, and retained legacy routes; and
- after caller proof, remove obsolete `REPRESENTATIVE_CARDS` image mappings,
  unused tracked representative assets, and duplicate selection branches while
  retaining required English Cache-B and compatibility paths.

Effect: the initially visible Landing cards load locally in Chinese, all other
cards remain bounded on demand, and the old duplicate image systems are reduced
without weakening the English fallback.

Each item is a separate authorization and Owner-acceptance subject. This
decision changes documentation only and authorizes none of them, no source or
image request, no code or Schema change, no Pages deployment, and no production
operation.
