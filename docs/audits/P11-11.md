# P11-11 — Legacy entry-point audit and owner deletion list

## Purpose

Audit every repository-root Python entry point before any deletion or move.
This task records current callers, verified replacements, remaining migration
work, and a plain owner decision list. It does not delete or move an entry
point, change executable behavior, edit a workflow, regenerate data, alter a
statistical formula, change a public path, or modify either front end.

The audit baseline is `master` commit
`43476a3076127bbae7b6950f8c7da9099ef044d0`.

## Method and deletion gates

The audit enumerated all 26 tracked Python files at the repository root and
searched their literal file names and import names across workflows, source,
tests, configuration, current documentation, and retained historical audits.
It inspected the installed console-script declarations, exercised the three
installed commands with `--help`, compared wrapper and package implementations,
and reviewed the tests that protect format authorization, dispatch, generated
output, and compatibility behavior.

The historical cleanup contract requires all of the following before an entry
point is deleted:

1. its replacement is verified;
2. workflows use the replacement;
3. tests cover the replacement;
4. current documentation uses the replacement; and
5. rollback is possible.

Repository searches cannot identify an unrecorded external user who invokes a
root script from another checkout. P11-12 must therefore treat the parent
commit and its pull-request diff as the rollback source and must describe the
removed compatibility commands prominently. Retained historical documents
must not be rewritten merely because they truthfully name commands that
existed at the time.

## Maintained tool to relocate

`validate_standard_quality.py` remains a useful explicit verifier for the
frozen, aggregate-only Standard quality baseline. The README documents it and
`tests/test_standard_quality_baseline.py` covers its deterministic result. It
is not a production entry point, and it should not remain mixed with active
workflow launchers at the repository root.

Recommend moving it to `tools/validate_standard_quality.py` in P11-12. Before
the move, replace its `classify_standard` dependency with the equivalent
package APIs, update its test and README command, and confirm that it still
reads only frozen fixtures. Do not change the frozen aggregates.

## Owner decision list

The recommended P11-12 decision is one coherent cleanup:

1. delete the nine compatibility wrappers listed above;
2. delete the seven obsolete or one-off scripts listed above;
3. delete `unknown_clusters.txt` and `unknown_highperf.txt` with their retired
   generators;
4. move `validate_standard_quality.py` under `tools/` while preserving its
   exact aggregate result;
5. keep the nine active root workflow and publication tools unchanged; and
6. update only current README commands and live contract tests. Preserve
   historical audits, migrate the P3 contract fixture from a current-existence
   assertion to an explicitly historical record, and retain Git rollback.

This means 18 deletions, one move, and nine retained root Python tools. Owner
selection of this list records the intended cleanup scope but does not itself
authorize P11-12 implementation. P11-12 would not authorize a workflow
redesign, output regeneration, statistical change, public-path change,
front-end change, production dispatch, commit, or remote publication.
