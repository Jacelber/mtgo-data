## Problem

The format registry deliberately separates three states: runnable, eligible
for production, and completely public. Most product boundaries followed that
model, but classifier-closure default discovery treated every executable
format as public. A private executable format therefore reached public-only
publication inspection and failed with a misleading downstream error.

Two adjacent controls were incomplete. Repository validation did not always
recompute `stats/catalog.json` when the format registry changed, and pull
request CI did not explicitly route changes in the shared admission code to
the third-format and classifier-closure contract tests.

## Repair

`src/mtgmeta/catalog.py` now owns one complete-public resolver. Eligibility is
computed only from the format registry's `public` and executable state, the
required MTGO capabilities, and the required product files. The stored
`stats/catalog.json` is never an input to that decision.

Catalog generation, classifier-closure discovery and explicit format
selection, and repository catalog-consistency validation reuse that resolver.
Default closure discovery selects only complete public formats. Explicitly
requesting a private executable format returns `INVALID` before staging or
writing any output and explains that registry `public` is false.

Repository validation recomputes the catalog with its retained generation
timestamp whenever `configs/formats.yaml`, `stats/catalog.json`, or the shared
catalog implementation changes. Both a private format marked available and a
complete public format marked unavailable fail as catalog drift.

CI adds one `public-admission` trigger with an exact path set. It runs only
`tests/test_mtgo_third_format.py` and `tests/test_classifier_closure.py`; it
does not use a broad source-directory trigger or full pytest.
