# P10-09 production job split

## Scope and authorization

The owner authorized P10-09 local implementation on 2026-08-01. The task
splits the scheduled MTGO production workflow into separate fetch, build, and
publish jobs. It preserves the daily schedule, manual master-only dispatch,
format registry boundaries, clean-checkout regression, production-candidate
acceptance, generated-path boundary, and published-commit confirmation.

The isolated workspace is `C:/tmp/mtgo-data-p10-09-20260801-01`, branch
`codex/p10-09-production-job-split`, based on P10-08 merge commit
`3cded88f689b42377370240921e2975d53f97ab3`.

This task does not authorize a production dispatch, live source fetch,
generated-data change, direct development on `master`, storage migration,
resumability, failure-issue creation, Pages setting change, front-end change,
statistical change, compatibility migration, history rewrite, commit, remote
publication, pull request, or merge.

## Job boundary

`fetch` is read-only. It runs the complete clean-checkout regression suite,
captures the candidate baseline, fetches the existing approved event and match
inputs, packages the input trees and baseline with SHA-256 checksums, and
uploads the one-day `mtgo-fetch-candidate` artifact.

`build` is read-only and needs `fetch`. It checks out the same immutable
trigger commit, verifies and restores the fetched artifact, runs the existing
statistics, matchup, completeness, Top 8, Pickup, hierarchy, metadata,
catalog, and strict classification commands, then runs candidate, repository,
rule, and Schema validation. Only after those checks pass does it package the
allowed output roots with a checksum in the one-day `mtgo-build-candidate`
artifact.

`publish` needs `build` and is the only job with `contents: write`. It checks
out the same trigger commit, verifies the output artifact, rejects archive paths
outside `data/`, `stats/`, `reports/`, and `fetched.txt`, restores that bounded
output, commits it only when changed, pushes to `master`, and confirms both a
clean workspace and the exact remote commit.

The artifacts are immutable, short-lived intra-run handoffs. They are not an
external storage provider, durable data archive, or resume checkpoint. P10-10
retains sole ownership of restart behavior, and P10-11 retains sole ownership
of failure-issue creation.

## Test-first evidence

The focused workflow test was first rewritten to require all three jobs,
least-privilege permissions, immutable artifact checks, unchanged validation
ordering, and publication confined to the existing generated roots. Against the
pre-split workflow it failed with 10 expected assertions because that workflow
had one `update` job and workflow-wide write permission. After the workflow
split, all 13 focused production-workflow tests passed on Python 3.12.

Impact discovery then found one Phase 6 cross-layer test that still addressed
the removed `update` job. It now checks the product and hierarchy environment
on the `build` job, the sole job that generates those product layers.

## Validation result

The focused workflow contract first failed with 10 expected assertions against
the former single-job design, then passed after the split. The final affected
cross-layer suite passed 84 tests in 6.05 seconds on Python 3.12.7. The complete
suite passed all 654 tests in 407.17 seconds on Python 3.12.7.

An initial task-local Python runtime crashed inside an existing Top 8 regression
test with a Windows access violation during garbage collection. The same target
test passed in 73.85 seconds under the installed Python 3.12.7 runtime used for
the final suite, which then completed without an error. This was a local runtime
failure, not a failed assertion or a workflow behavior change.

Repository validation passed for 135 Python files, 1,613 JSON files, 22 YAML
files, 30 references, and 1,909 hygiene paths. Standard rule validation and
public Schema validation of all 69 documents passed. YAML parsing, `git diff
--check`, changed-path review, and protected data, statistics, front-end, and
Pages-input path review also passed. No external source request, generated-data
change, production dispatch, remote write, Pages deployment, or front-end
change occurred.
