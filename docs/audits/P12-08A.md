## Implemented result

- MTGO statistics and Tabletop overview use dedicated semantic card markup at
  780 CSS pixels and below while the existing desktop tables remain unchanged
  above the breakpoint. Both layouts are produced from the same sorted records,
  formatters, state, URL contract, and lazy-loaded detail sources.
- MTGO cards emphasize high-score share, average points, and Top 8 share, then
  keep high-score count, Top 8 count, and high-score-to-Top-8 conversion visible
  in the same card.
- Tabletop cards emphasize metagame share with deck count, average points, and
  win rate with valid-match count. Literal W-L-D, completion rate, and the
  event's advancement or high-score metric remain visible below them.
- Parent and subtype cards use explicit expand-subtype or view-deck buttons.
  Subtypes have a labelled, indented accent treatment; deck detail is inserted
  directly under its originating card. Existing single-detail and multi-parent
  expansion state is preserved.
- Mobile sort selectors and direction buttons reuse the established sort keys,
  default directions, URL parameters, history behavior, and live status region.
  Rendering restores focus to the initiating control and does not force a long
  list back to the top.
- Detail and subtype expansion keep focus on the trigger. When newly inserted
  mobile content begins outside the viewport, the smallest nearest scroll makes
  its start visible. Detail closure returns focus to the originating button.
  Equivalent controls exchange focus across the 780/781-pixel boundary without
  losing expansion or sort state.
- Matchup matrices and Top 8 remain bounded horizontal comparisons rather than
  lossy cards. Their first identity column is sticky; a localized cue and right
  fade disappear after the first horizontal scroll for that view.
- Owner review identified that the inherited 230-pixel matchup identity width
  still dominated a 375-pixel screen. The mobile identity column now uses a
  96-to-132-pixel responsive width, compact toggle padding, aligned names with
  or without a subtype toggle, and a two-line ellipsis only for actual
  overflow. The redundant toggle circle is removed while the whole name stays
  clickable. Matchup data cells use a 52-pixel mobile width. The reviewed
  in-app browser showed 4.01 data columns at 375 pixels without cell or page
  overflow.
- The opponent-name header is reproduced in an inert visual-only sticky layer
  after the source header reaches the viewport top. It remains visible during
  vertical page scrolling and mirrors the matrix horizontal offset on both
  small and desktop widths without creating a second semantic matchup table.
- Weekly Pickup keeps its existing card and disclosure behavior. Only its
  heading and secondary metric wrap on narrow screens.
- Main mobile actions meet a 44-pixel target floor. Transitions are limited to
  light border and shadow feedback and continue to honor reduced motion.
- Mobile rendering and interaction live in two focused classic-script assets;
  the existing 25KB per-file split contract remains intact without introducing
  a build step, module loader, or framework.
