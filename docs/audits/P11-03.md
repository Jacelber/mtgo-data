# P11-03 — Narrow mypy baseline audit

## Scope

P11-03 introduces a strict mypy baseline for four stable, source-independent
shared modules only:

- `src/mtgmeta/card_names.py`;
- `src/mtgmeta/deck.py`;
- `src/mtgmeta/rules.py`;
- `src/mtgmeta/classifier.py`.

The task adds a pinned development dependency, CI command, configuration
contract test, and documentation. It does not modify production data, public
paths, statistical behavior, front-end source, or the protected event `434455`
bytes.

## Scope selection

All four selected modules are used by both MTGO and Tabletop pipelines and
already have typed public interfaces. A first strict scan found five errors in
`rules.py` and `classifier.py`: validated string identifiers remained typed as
possibly absent values, and an optional subtype identifier reached a dictionary
lookup without an explicit branch.

The first scan also reached unselected `config.py` and `reports.py` through
imports. Those 14 findings remain outside this initial task. `follow_imports =
"skip"` prevents their accidental inclusion while preserving strict checking
within the four explicit modules. No global ignore, per-module ignore, or
silent non-strict baseline is used.

## Implementation

- Pin `mypy==2.3.0` and its resolved direct transitive dependencies.
- Add a strict Python 3.12 mypy configuration for the four selected modules.
- Add `python -B -m mypy` to the existing read-only CI static-validation job.
- Add a contract test that fixes the version, strictness, import boundary, and
  exact module list.
- Use a `TypeGuard[str]` for existing identifier validation and an explicit
  optional-subtype branch, preserving runtime behavior.
