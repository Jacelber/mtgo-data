## Problem

The Tabletop product has validated hierarchical matchup documents for one
event, but no side-effect-free reference calculation for combining compatible
events. Averaging their already-calculated rates would overweight smaller
events, and trusting parent matrices independently would create a second source
of truth that could drift from the underlying leaf counts.

P13-01 also needed to freeze which incompatibilities stop aggregation before
P13-02 defines versioned result and catalog contracts.

## Solution

Add `aggregate_multi_event_matchups` in
`src/mtgmeta/melee/multi_event_matchup.py`. The function accepts only in-memory
inputs:

- two or more event pairs containing one validated current `meta` document and
  its validated single-event `matchup` document; and
- the complete maintained canonical hierarchy for the shared taxonomy.

It performs no file, network, source-collection, Schema-publication, catalog,
or front-end operation. Exact duplicate inputs are deduplicated by numeric
event ID; conflicting duplicates fail closed. Event IDs and contributor IDs
are returned in numeric order.

For every distinct event, the function verifies:

- Melee source and Tabletop product identity;
- one shared Constructed format;
- the explicit supported matchup Schema version `1.0.0`;
- non-blocking `pass` or `warning` quality;
- the `all_constructed` scope in matching metadata and matchup declarations;
- matching taxonomy Schema versions and SHA-256 values within and across
  events;
- stable parent and leaf meanings against the supplied canonical hierarchy;
- event hierarchy and matrix-order reconciliation independent of each event's
  presentation order;
- complete non-negative leaf matrices with inverse cells; and
- source, exclusion, directed-observation, and physical-match conservation.

After admission, it unions only observed stable identities in canonical order,
sums leaf wins, losses, and normal played draws, rolls the combined leaf matrix
up to parents, and rebuilds non-mirror overall records. Literal win rate and the
95% Wilson interval come from the maintained shared `literal_match_record`
helper. The low-sample flag is true only for 1 through 19 matches; zero remains
unavailable and 20 clears the count-only warning. Every non-empty emitted cell
and overall record identifies its contributing event IDs.

The P13-01 result is deliberately an unversioned in-memory reference object.
P13-02 owns the public Schema version, input path and digest provenance,
catalog admission evidence, and consumer-facing result contract. This task
does not pre-empt those decisions.

## Stable failure vocabulary

`MultiEventMatchupError.code` is restricted to this explicit set:

- `blocking_quality`;
- `duplicate_event_conflict`;
- `event_identity_mismatch`;
- `format_mismatch`;
- `identity_metadata_mismatch`;
- `invalid_event_input`;
- `matrix_invariant_failed`;
- `missing_all_constructed_scope`;
- `product_mismatch`;
- `source_mismatch`;
- `taxonomy_digest_mismatch`;
- `taxonomy_version_mismatch`;
- `too_few_events`; and
- `unsupported_matchup_schema`.

An internal call using an unregistered code raises an assertion rather than
silently expanding the external vocabulary.

## Synthetic acceptance subjects

`tests/test_melee_multi_event_matchup.py` covers:

1. two compatible Modern events with different observed identity subsets and
   a per-event presentation order different from the canonical output order;
2. a raw-count weighted result that differs from the simple mean of event
   percentages;
3. normal played draws in the literal denominator;
4. real mirror records retained on the diagonal and excluded from overall;
5. explicit `Unknown` preservation;
6. unsorted and exact-duplicate input IDs without double counting;
7. conflicting duplicate, cross-source, cross-product, and cross-format
   rejection;
8. taxonomy version, taxonomy digest, and identity-metadata mismatch rejection;
9. unsupported matchup Schema rejection;
10. blocking quality and missing `all_constructed` rejection;
11. the exact 19/20 low-sample boundary; and
12. inverse-cell, parent-roll-up, included-match, exclusion, and directed-
    observation reconciliation.
