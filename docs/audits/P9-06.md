## Purpose and boundary

P9-06 makes the existing Tabletop Major Events front end consume the event
structure and scope set published by P9-05. The consumer now distinguishes
`mixed`, `constructed_day2`, and `constructed_single_stage` without inventing
unsupported stages or silently presenting one event as a multi-event result.

The task changes only the static Tabletop consumer, its bilingual copy and
style, focused tests, and status documentation. It does not fetch or admit a
real event, modify the whitelist, write generated statistics, alter a public
Schema or formula, dispatch a workflow, change MTGO products, or implement the
Phase 11 raw-count multi-event aggregation.

## Structure dispatch

| Event structure | Declared scopes rendered | Advancement column | Mixed selection-bias warning |
| --- | --- | --- | --- |
| `mixed` | `day1`, `day2`, `all_constructed` | existing high-score output | retained |
| `constructed_day2` | `day1`, `day2`, `all_constructed` | Day 2 conversion | omitted |
| `constructed_single_stage` | `all_constructed` only | high-score output | omitted |

The committed mixed event `434455` remains the production regression
baseline. Its existing Day 1 and Day 2 high-score column is deliberately
preserved: P9-06 dispatches the new pure-structure advancement metric without
deleting an accepted mixed-event feature.

For pure Day 2 events, the conversion value is present only where the backend
declares it. Other scopes display the existing unavailable mark rather than a
fabricated value. Single-stage events expose no Day 1 or Day 2 control.

## Scope and multi-event state

The scope resolver reads each catalog entry's exact `scope_order`:

- one selected event keeps a requested supported scope;
- an unsupported scope falls back to that event's declared default;
- selecting a second event forces `all_constructed`;
- stage controls represented by the selected events remain visible but
  disabled, with a bilingual explanation;
- returning to one event restores that event's last supported single-event
  scope, or its default when no supported preference exists.

Event Overview remains single-event. Matchup selection may hold more than one
event, but P9-06 does not aggregate their matrices. Until Phase 11 supplies
canonical summed W-L-D output, the front end shows an explicit unavailable
state and hides the active event summary and matrix. This prevents the
previous single loaded event from being mistaken for a merged result.

## Regression evidence

The local production entry was served from the isolated workspace and reviewed
in a real browser:

- event `434455` retained all three mixed scopes;
- its disqualification and mixed Day 2 selection-bias notices remained
  visible;
- the Tabletop overview retained the high-score column;
- switching to Day 1 produced the existing overall high-score count of `168`;
- switching to Matchup Win Rates rendered the existing matrix;
- the single-event Day 1 control remained enabled.

Controller tests use deterministic synthetic catalog entries to cover pure Day
2, pure single-stage, mixed presentation, multi-event locking, and supported
scope restoration. No synthetic event was added to the production catalog.
