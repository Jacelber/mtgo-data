## Purpose and boundary

This audit establishes the current public consumer baseline for Phase 8. It does
not change production HTML, JavaScript, CSS, Schemas, generators, statistics,
retained data, workflows, or public JSON. It does not make the P8-04
completeness decisions or freeze a visual design.

The evidence consists of a local static-browser inspection, source inspection,
and bounded reads of the committed public products for Standard and Modern. The
audit used the locally served isolated checkout, not a production update.

## Current browser behavior

The current `/index.html` is a single MTGO page. Its visible navigation order
is product view first, then format:

1. `MTGO official event statistics`
2. `MTGO matchup win rates`
3. `Weekly Pickup`
4. format buttons: Standard, disabled Pioneer, Modern

This is the reverse of the approved format-first hierarchy. The format list and
the three product views are hard-coded in `assets/js/mtgo.js`; they are not
read from generated catalog data. There is no MTGO weekly Top 8 view and no
Tabletop Major Events entry point. `melee/index.html` does not currently exist.

The MTGO matchup view already supplies the valuable interaction baseline:
parent-level display, independent row/column expansion, and a global
`Expand all subtypes` control. Its current visible subtype text is the bare
subtype name, for example `Gruul`, rather than a self-contained label such as
`Gruul Broodscale Combo`. The Phase 8 UI must consume a generated public
label; it must not compose or rename that label in the browser.

## P8-02 prototype constraints

P8-02 should use local, disposable HTML/CSS/JavaScript only. It should show:

- a format-first shell with an explicit unavailable-product treatment;
- the five approved product destinations without merging MTGO and tabletop state;
- parent-default, eligible-parent expansion, and global subtype control for
  statistics and both matchup axes;
- subtype detail behavior: expandable parent reveals subtypes only, while a
  subtype opens detail;
- a complete-week Top 8 selector and exact-deck detail state;
- completeness display states for available, unavailable, and excluded data;
- the tabletop event, scope, and quality-warning layout.

The prototype may use clearly labelled mock payloads for fields that do not yet
exist. It must not invent formulas, classify decks, or make an external design
service request. Superdesign remains outside this task and requires the
separate approval gate in DEC-051.

## Conclusions and stop point

The audit confirms the planned Phase 8 sequence. Existing hierarchical matchup
and subtype construction data are reusable, but catalog-driven navigation,
self-contained labels, Top 8 presentation data, range-specific matchup
completeness, high-score decklist completeness, and the tabletop page are not
implemented. No P8-04 formula, output shape, or final UI decision has been
made here.

P8-01 stops pending owner acceptance. The next task is P8-02 only after
separate authorization; P8-03 remains the mandatory UI and consumer-contract
freeze before any Phase 8 backend production work.
