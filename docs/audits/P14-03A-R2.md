# P14-03A-R2 — First-name review bootstrap

## Scope

This repair adds one explicit private diagnostic mode to the shared MTGO weekly
classification review exporter. It resolves the first-name review dependency
without changing taxonomy rules, stable identities, statistics, approved-name
authority, public admission, Landing output, or maintenance completion.

Artifact impact: `internal_diagnostics`.

## Contract

`mtgo --name-review-bootstrap` requires one registered executable non-public
format with the `classification` capability, one already-ended canonical ISO
week, and an output path outside the repository. Validation finishes before an
output directory is created. The exporter retains the formal weekly record
selection, classification, ordering, locators, priority reasons, event facts,
and high-score calculation, while continuing to omit decklists.

The generated `weekly_classification_name_bootstrap` document uses schema
version `1.0.0` and status `pending_owner_review`. Its `name_candidates` reuse
the Landing editorial taxonomy enumeration and English composition and cover
every parent and subtype, including identities absent that week. Approved
Chinese names are labeled existing references; missing names and suggestions
are null. `bootstrap_subject_digest` is the normalized-JSON digest of the whole
document excluding only the digest field itself.

The bootstrap has no `classification_review_digest`. Completion APIs and both
completion CLI paths reject it by type or pending status even if a syntactically
valid formal digest is inserted. Publication admission remains unchanged and
continues to reconstruct a strict formal review.

## Local acceptance boundary

Acceptance uses synthetic retained events only: missing-name formal rejection,
complete parent/subtype enumeration, unchanged classification record behavior,
pre-write scope/output rejection, completion isolation, and one actual exporter
to external JSON followed by `mtgo-detail`. No real Pauper review material,
event collection, public output, production generation, or later Phase 14 work
is part of this task.

The implementation acceptance passed all 19 focused tests in
`tests/test_weekly_classification_review.py` and the changed-scope repository
validator from frozen base `f86d0b2742df4fcffad4e4c45bae2e66615740cf`.
Completion review then corrected the bootstrap output boundary to reject every
repository-internal path, not only Pages-admitted paths. The two directly
affected external-output/detail checks and the six pre-write scope/output cases
passed after that correction; `git diff --check` also passed. These checks used
synthetic repositories and repository-external temporary output only.
