# P10-10 — MTGO fetch-stage resumability audit

## Scope

P10-10 adds bounded restart behavior only to the read-only MTGO input-collection
stage in `.github/workflows/update.yml`. It does not dispatch production,
change fetched or generated data, alter statistical code or formulas, change
the two front ends or public URLs, add a storage provider, create failure
issues, or grant repository-write permission to fetch or build.

## Restart contract

1. After clean-checkout regression and baseline snapshot succeed, the fetch job
   creates a versioned manifest for every configured event and match operation.
2. A completed operation is recorded only after its existing command returns
   success. Failed operations remain pending; the job continues attempting the
   other pending operations, then fails overall.
3. On that failure, the job uploads `mtgo-fetch-checkpoint` for seven days. It
   holds only `data/`, `fetched.txt`, the original clean baseline, the manifest,
   and SHA-256 checksums.
4. A future run may locate the newest unexpired checkpoint only when its Action
   metadata reports the exact same master SHA. It additionally verifies the
   manifest repository, full SHA, event/match plan, checksum set, and archive
   path boundary before restoring it.
5. Only verified `complete` operations are skipped. The normal
   `mtgo-fetch-candidate` is still made only after every operation succeeds;
   build and publish do not consume the restart artifact.

## Permission and data boundary

The fetch job keeps `contents: read` and gains only `actions: read`, which is
needed to find an artifact from an earlier workflow run. It has no repository
write permission. Build stays `contents: read`, publish remains the sole
`contents: write` job, and no `issues: write`, Pages, OIDC, cloud-storage, or
credential permission is introduced.

The checkpoint is not durable storage: it expires in seven days, has no public
data path, and is never restored across a changed commit or collection plan.
The current public Git archive remains the durable approved data path.

## Required local validation

Run the focused checkpoint and workflow contract tests, then the full Python
3.12 suite and the repository, rule, and Schema validators. A production
dispatch is outside this audit and requires a separate owner authorization.

## Local implementation result

The focused checkpoint and workflow contract suite passed 18 tests in 0.55
seconds. The complete Python 3.12.13 suite passed all 659 tests in 412.17
seconds. Repository validation passed for 137 Python files, 1,613 JSON files,
22 YAML files, 30 references, and 1,912 hygiene paths. Standard rule validation
and public Schema validation of 69 documents also passed. No production
workflow was dispatched, no fetched or generated data changed, and no front-end
path changed. Local implementation stops for owner acceptance before commit,
remote publication, merge, or any real production-data dispatch.
