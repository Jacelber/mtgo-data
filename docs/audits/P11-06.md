# P11-06 — Native JavaScript test baseline

## Scope

P11-06 adds native Node.js tests for the existing Phase 8 matchup model and
for exact Chinese and English translation-key parity. It does not change
statistics, generated data, public paths, or visual product behavior.

## Implementation boundary

- Use Node's built-in `node:test` runner with no npm manifest, package
  installation, or front-end build step.
- Run the native suite through the established pytest workflow because that
  workflow already requires Node.js for existing Phase 8 contract tests.
- Expose only the current dictionary keys through `P8I18n.translationKeys`;
  the function does not mutate dictionaries or alter translation lookup.
- Test literal W-L-D aggregation across collapsed and independently expanded
  matchup axes, including totals, match counts, and win rates.

## Acceptance evidence

Local validation passed with the native Node suite (3 tests), the focused
front-end regression group (25 tests), and the complete pytest suite (671
tests). Ruff, mypy, repository, rule, Schema, 434455 compatibility, and Pages
contract checks also passed. The detailed evidence is recorded in
`docs/STATUS.yaml` before owner acceptance. No browser-visible verification is
required because P11-06 changes test coverage only.
