## Purpose and boundary

P8-02 established and received owner acceptance for the Chinese-first local
interaction prototype. P8-03 converts those accepted interaction decisions
into one reviewable UI-to-data consumer contract before any Phase 8 backend
product is designed.

This task changes documentation only. It does not change a production page,
JavaScript, CSS, generator, Schema, fixture, statistical output, retained data,
workflow, catalog, or public path. It does not authorize P8-04 or remote
publication.

The existing production implementation remains a compatibility baseline. Where
the accepted target differs from published output, this document labels it a
target and assigns the versioned migration to P8-04. It must never be inferred
that a documentation freeze has already recalculated public data.

## Contract hierarchy

The following sources are intentionally layered:

1. `docs/PROJECT_SCOPE.md` defines the product and source boundaries.
2. `docs/STATISTICS_SPEC.md` defines the approved target statistical meaning
   and explicitly identifies the still-published legacy compatibility period.
3. `docs/DATA_ARCHITECTURE.md` defines the consumer obligations without
   prematurely choosing versioned JSON field names.
4. This audit records the detailed component behavior, Chinese copy baseline,
   English-copy proposal, consumer matrix, and P8 task ownership.

If a later UI preference would require a new statistic, denominator, event
eligibility rule, or source merge, it is not an implementation tweak. Stop and
obtain a separate approved P8-04 contract amendment.

## Frozen interaction contract

### Format, product, and availability

- Constructed format is the primary selector.
- The visible product order is `MTGO官方数据统计`, `MTGO对阵胜率`,
  `MTGO八强牌表`, `实体大赛`, and `每周精选套牌`.
- Product availability is generated-catalog data, never a hard-coded format
  assumption. Available products remain visually available.
- On a format switch, preserve the current product when it is available for
  the newly selected format. Otherwise select the leftmost available product.
- An unavailable product remains visible but disabled. Hover, focus, and a
  non-navigating click use the Chinese baseline `暂未上线，正在开发中`.
- MTGO and Tabletop Major Events remain separate products, entry points,
  payloads, caches, quality claims, and statistics.

### Hierarchy and construction details

- Parent archetypes are the default table and matrix identities.
- Only a parent with two or more maintained subtypes is expandable. Its
  plus/minus toggle hangs to the left; all parent labels retain one aligned
  text edge. Zero- and one-subtype parents have no control.
- Expanding retains the parent row or column and inserts self-contained subtype
  children beneath or after it. It never substitutes a subtype for its parent.
- Row and column axes of a matchup matrix expand independently; one global
  control expands or collapses all eligible parents.
- Expansion must not change the positions or widths of already visible metric
  columns. A horizontally scrollable matrix may grow internally, but its
  existing cells must not shift because an axis is expanded.
- A subtype display label is supplied by generated data and is complete by
  itself, for example `Grixis Prowess`. Browser code must not compose it from
  colors or rename classifier IDs.
- Selecting an expandable parent reveals children only. It does not show a
  cross-subtype averaged deck. Selecting a subtype opens that subtype's own
  representative deck, average deck, deviation, recent construction change,
  card differences, and explanatory text. A parent with zero or one subtype
  may retain a single most-specific detail view.
- Official-statistics construction detail renders inline immediately below the
  selected subtype row, preserving the current production interaction rather
  than moving detail to the bottom of the page.

### Visible match-result semantics

- The visible Chinese label `胜率` means literal valid-match win percentage:
  `W / (W + L + D)`.
- A normal played draw remains a valid match in the denominator and contributes
  zero wins. Existing exclusions for intentional draws, byes, no-shows,
  awarded wins, administrative/unknown results, Draft, and primary-Swiss
  playoffs remain unchanged.
- Overview primary values and matrix `整体` include mirror matches. The
  non-mirror W-L-D record and rate remain supporting output, not the only
  visible rate.
- Both MTGO and Tabletop matrices display real diagonal mirror cells with
  W-L-D, literal win rate, confidence interval, and normal sample-state
  treatment. The diagonal is never replaced by an unavailable dash solely
  because it is a mirror.
- The UI may format or roll up explicitly supplied canonical counts, but it
  must not independently define a rate, average precomputed percentages, or
  reconstruct a missing statistic.

### Tabletop Major Events requirements

- The visible product name is `实体大赛`; source metadata may identify Melee.
- Product choice precedes event selection: Event Overview uses a one-event
  dropdown; Matchup uses a compact scrollable multi-select checkbox pane.
- Entering Matchup includes the active overview event. Returning to overview
  opens the most recently selected matchup event. Multi-event aggregation is
  available only for compatible, explicitly selected same-format events.
- The mixed reference event defaults to all Modern Swiss. Scope controls expose
  only scopes supported by all currently selected events.
- Event Overview begins with a non-expandable overall row containing the
  applicable aggregate/average values. It is not a synthetic archetype.
- Event structure and scope control metric availability. Mixed all-Constructed
  high-score values are explicitly unavailable; Day 2 carries selection-bias
  context rather than a pure deck-conversion claim.
- Preserve source link, event date, event ID, quality, Unknown, disqualification,
  Draft/playoff exclusions, completeness, selection-bias context, W-L-D,
  sample, and confidence-interval information.
