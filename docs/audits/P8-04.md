# P8-04 Statistical and Public Data Contract

## Purpose

P8-04 converts the owner-accepted P8-03 consumer requirements into one
machine-verifiable target contract before any producer or production page is
changed.

## Boundary

This task adds:

- `schemas/phase8-public-contract.schema.json`;
- `tests/fixtures/phase8_public_contract.json`;
- `tests/test_phase8_public_contract.py`;
- the exact formulas, rounding, unavailable states, and migration boundary in
  the authoritative documents.

It does not change:

- MTGO or Melee generators;
- current public JSON or `schemas/manifest.json`;
- workflows or source fetching;
- classification rules;
- front-end code or deployed behavior.

## Contract decisions

### Match records

Target records retain W-L-D counts, match count, literal win rate, formula
identifier, and Wilson 95% interval. Normal played draws remain in the
denominator and contribute no wins. All-match records include mirrors;
non-mirror records are supporting output. Real diagonal cells remain available.

### Videre coverage

For one selected interval:

`expected = available + deferred + missing`

`completeness = available / expected`

Excluded events are diagnostic only. An empty or indeterminate admitted
population is unavailable, not zero.

### MTGO high-score decklist completeness

For each eligible event, use the existing player-count round table, the existing
high-score threshold, and the fair decisive-match binomial tail. Keep event
expectations unrounded, sum them, and round only the displayed expected count
half-up. The rate is capped at one while `exceeds_model` preserves an observed
count above the model.

The retained Standard fixture for 2026-07-13 through 2026-07-19 contains seven
eligible events, 97 observed high-score decklists, a raw expectation of
99.1875, a displayed expectation of 99, and completeness `0.977946`.

An event without usable Swiss-score evidence is unsupported and excluded from
both observed and expected totals. It is never silently counted as zero.

### Weekly Top 8

A complete Monday-through-Sunday week retains every admitted event and exactly
ranks 1 through 8. An unavailable placement remains explicit with null
identity, exact-deck, and comparison fields. An available subtype deck carries
the exact event list and a stable reference to its subtype comparison base.

### Tabletop and subtype contracts

Subtype display names are self-contained and never guessed by the browser.
Tabletop events expose their structure, default and supported scopes, direct
scope summaries, all-match and non-mirror records, and compatible multi-event
matchup scopes.

## Compatibility strategy

The new Schema is deliberately absent from the production manifest. Current
public outputs remain governed by their current Schemas and legacy formula.
P8-05 and P8-06 must create product-specific generated documents, validate them,
and coordinate consumer migration. A field named `win_rate` is target semantics
only when its record explicitly declares
`win_rate_method: "wins_over_valid_matches"`.

## Deferred source-quality investigation

MTGO event `12847150` is not repaired in P8-04. Its retained archive has 32
published deck entries but lacks Swiss-score fields, while the owner verified
that the current official event page contains complete data. After P8-04 owner
acceptance, a separately authorized task must:

1. trace the original fetch response and parser/completeness decision;
2. determine whether the source was temporarily incomplete, the parser accepted
   a partial representation, or the completeness gate missed required fields;
3. reproduce the condition where retained evidence permits;
4. recommend fetch-time validation, bounded retry/defer behavior, diagnostics,
   and a regression fixture;
5. avoid replacing retained evidence or changing production fetch behavior
   without separate approval.

tests, existing public manifest validation still covers the same 52 documents,
the complete test suite and repository validators pass, and the final diff
contains no producer, public-data, workflow, rule, or front-end change.
