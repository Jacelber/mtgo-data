## Root cause

P14-03A connected the workbook validator to `_catalog_from_workbook` and passed
the `Field Guide` rows to it. The five-sheet carrier defines that sheet only as
field documentation, so a normal workbook contained no bilingual-name rows and
failed complete taxonomy coverage before import.

The same import path then serialized a catalog derived from workbook rows back
to `configs/mtgo_archetype_names.yaml`. This incorrectly coupled weekly Landing
editorial import to classifier-name maintenance.

The historical public binding also digested the complete name and visual
documents. Adding a third format would therefore stale Standard and Modern
objects even when their historical subject had not changed. The name consumer
selected its digest scope from the invocation's `private` flag instead of the
review document version that defines the stored binding.

## Repair

- Workbook validation now reads and validates the approved
  `configs/mtgo_archetype_names.yaml` catalog for every selected format. `Field
  Guide` remains a required documentation sheet but is not parsed as name data.
- Landing import never rewrites the name authority. An in-repository import
  leaves the file untouched; an external import copies its original bytes.
  Existing result fields remain present.
- Review `1.0.0` name bindings use the ordered historical Standard/Modern
  projection. Review `1.1.0` bindings use only the review document's format.
  The importer and consumer call the same digest function, and the consumer
  selects the rule from `review.schema_version`.
- Public Landing visual bindings use the historical Standard/Modern projection.
  Private Landing `1.3.0` bindings use only the selected format.
- No real review, name, visual, known-state, representative-card, or generated
  Landing file is migrated or rewritten.

  passed. The catalog supplied all taxonomy names, in-place authority bytes and
  the external copy were identical, review `1.1.0` was imported, and private

  index documents. All three generated documents passed their existing Schema
