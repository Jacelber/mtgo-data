# P9-07S resumable large-event collection

Date: 2026-07-30

## Purpose and boundary

P9-07 established that the approved Standard `constructed_day2` pilot event
`419742` exposes 893 decklists and needs 1,085 complete-archive responses. The
previous complete collector stopped at 500 decklists or 500 responses and
deleted all partial work after any failure. P9-07S replaces those assumptions
with a bounded, resumable collector suitable for reviewed large events.

This task changes the complete Melee raw collector, its CLI progress output,
the compatible raw-archive response ceiling, tests, and documentation. It does
not add an event to `configs/melee_events.yaml`, retain source responses in the
repository, generate production data, change a statistics formula, change the
front end, change a workflow, dispatch production, or authorize P9-08.

## Implemented state model

The complete collector now uses one event-local staging directory and one
checkpoint:

1. create `.complete-in-progress/` and
   `.complete-in-progress.json`;
2. discover tournament, standings, completed-round match, and decklist
   requests;
3. freeze the complete ordered request plan, its response count, and its
   SHA-256 identity;
4. save every successful response and its checkpoint metadata atomically;
5. on restart, verify every recorded file by path, byte count, SHA-256, and
   request identity before reusing it;
6. download only missing responses;
7. write the complete manifest atomically, rename the staging directory to the
   final snapshot, and remove the checkpoint.

An interrupted staging directory has no usable manifest. The parser and
retention boundary therefore reject it, and it cannot enter normalization,
statistics, or publication. A resumed run must reproduce the same frozen plan;
source-plan drift is an explicit error instead of an implicit mixed snapshot.

The CLI writes structured progress records to stderr so its existing
machine-readable final stdout remains compatible.

## Explicit limits

- complete-event standings/decklists: 5,000;
- completed rounds: 32;
- matches in one round: 2,000;
- complete-archive responses: 10,000;
- one response: 32 MiB;
- one archive: 256 MiB.

The generic configured raw-request collector retains its existing 500-response
limit. The public complete raw-archive Schema relaxes `responses.maxItems` from
500 to 10,000. This is backward compatible: every document valid under the
previous `2.0.0` boundary remains valid, so the schema version does not change.

A synthetic 3,000-player, 16-round event with 1,500 matches per round requires
4,081 responses and is admitted by the new budget. Values beyond the explicit
ceilings remain rejected.

## Temporary real-source acceptance

Event: `https://melee.gg/Tournament/View/419742`

The event was supplied through an in-memory copy of the reviewed configuration;
the whitelist was not edited. The run used anonymous public requests, the
collector's 0.3-second request pacing, and a temporary raw root under
`C:\tmp`.

- duration: 1,145.5 seconds;
- planned and completed responses: 1,085;
- response payload bytes: 14,041,447;

- old 500-response boundary crossed without failure;
- parsed standings: 893;

confirmed absent. No live response, identity-bearing source record, normalized
event, generated statistic, or publication artifact entered the repository.

## Operational follow-up

The collector can resume across processes only when the same raw root persists.
GitHub-hosted Actions workspaces are ephemeral, and P9-07S deliberately does
not add artifact/cache restoration or alter the production workflow. Before a
large event is added to the production whitelist, the production admission
review must choose and validate a persistent checkpoint transport. That is a
separate operational authorization, not a reason to weaken the collector's
local correctness boundary.

## Stop point

P9-07S stops after local implementation, real-source acceptance, cleanup, and
validation. Commit, remote publication, production dispatch, whitelist
activation, and P9-08 each remain separately controlled.
