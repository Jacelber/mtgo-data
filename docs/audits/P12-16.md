## Problem

The accepted Landing and retained views are already implemented, but the bare
MTGO entry still resets to Statistics and the generated catalog still names
Statistics as the default product. The visible home title also bypasses the
bare entry by hard-coding one Standard Landing query. Finally, catalog
generation exposes public MTGO product files independently, so a future public
format is not yet rejected when it has only part of the required MTGO product
set.

P12-15G already removed the standalone Pickup identity and preserved its legacy
URL normalization. P12-15E-I18N and P12-15E-UX already delivered localization
and the accepted interaction corrections. P12-16 must verify those behaviors;
it must not rebuild or redesign them.

## Implementation boundary

1. Set `mtgo-landing` as the generated catalog default only when the complete
   required MTGO product set is present.
2. Fail catalog generation for a public format missing any required MTGO
   product, including Landing. Tabletop availability remains a separate product
   and is not part of this MTGO completeness set.
3. Make bare-entry state consume the catalog default while preserving every
   explicit `product` URL.
4. Make both visible site titles link to the bare MTGO entry.
5. Preserve the existing legacy
   `product=weekly-pickup&week=<week>` normalization to the requested Landing
   feature week.
6. Add the Owner-directed white-black-green mana identity to the Modern
   `devoted-druid-combo` parent, matching its existing `abzan` child mapping;
   do not add renderer fallback or inference logic.
7. Keep Landing environment list rows at the parent level, but title each
   expanded detail with the subtype that owns its displayed best deck. Do not
   change the selected deck, average construction, deviation, or comparison.

No CSS, layout, classifier, formula, Schema, workflow, editorial content,
tournament data, frozen Pickup document, or protected `434455` byte is changed.
The only visual-metadata correction is the exact parent mana identity above.
