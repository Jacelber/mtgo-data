## Purpose

Implement the P8-04 range-specific Videre coverage, modeled MTGO high-score
decklist completeness, and literal MTGO win-rate contracts without changing
the deployed front end or reinterpreting legacy percentage fields.

## Public product

The `completeness_reporting` capability enables:

- `python -B -m mtgmeta.mtgo --format <standard-or-modern> build-completeness`;
- `stats/<format>/mtgo/completeness/index.json`;
- `stats/<format>/mtgo/completeness/{1,4,12,36}w.json`;
- metadata discovery through `completeness_catalog`;
- scheduled fail-closed generation before Top 8 and metadata.

The range and catalog documents use dedicated version 1.0.0 Schemas. Ten new
Standard/Modern documents increase the public manifest from 56 to 66 checked
documents.

## Videre evidence boundary

One selected interval admits the retained official event archives in that
closed date range. A usable non-empty Videre archive is available. An admitted
event without one is missing.

The fetch layer has no durable deferred-event ledger. P8-06 therefore does not
infer a temporary defer from archive absence. Production deferred lists are
empty unless a future reviewed status source supplies explicit evidence. This
prevents an unverified missing event from leaving the denominator.

## High-score model

Each eligible event uses its retained positive player count, the existing
player-count round model, the existing high-score threshold, and complete
Swiss-score evidence. Event expectations remain unrounded, the aggregate
display count rounds half-up, and the rate is capped at one with
`exceeds_model` retained.

Unsupported events are listed with reasons and contribute to neither observed
nor expected totals. The repaired retained production corpus has no unsupported
Standard or Modern events in the four generated intervals.

## Literal match records and compatibility

Every existing MTGO matrix cell keeps its draw-adjusted `win_rate`,
`ci_half`, sample flag, and mirror flag for the deployed consumer. It now also
contains `literal_record`, which declares `wins_over_valid_matches` and uses
literal wins for its Wilson interval.

Each hierarchical range also exposes:

- `parent_match_records`;
- `leaf_match_records`;
- primary `all_matches`;
- supporting `non_mirror`;
- physical `mirror_match_count`.

Real diagonal matrix cells remain present. Standard name-keyed aliases and
stable-ID parent/leaf compatibility fields remain available.
