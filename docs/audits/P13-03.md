## Problem

P13-01 and P13-02 define the accepted Python raw-count aggregation and
catalog-admission contract. The browser model had no equivalent pure function,
so later controller and renderer work could accidentally change counts,
intervals, stable identity order, warnings, or fail-closed behavior.

Repeating the complete Python suites in this task would not prove JavaScript
parity and would violate the repository rule that an already-proven risk is not
tested again without a new trigger.

## Solution

Add one dormant, side-effect-free `buildMultiEventMatchupContract` export to
the existing Phase 8 matchup model. It accepts prevalidated event inputs, the
canonical hierarchy, and catalog evidence; then it performs the same semantic
reconciliation and raw leaf W-L-D aggregation as the accepted Python contract.

The function supports only `all_constructed`, reconstructs parent and overall
records from leaf counts, uses literal draws in the denominator, emits the same
Wilson 95% interval and 20-match warning threshold, preserves canonical stable
ID order including `unknown`, sorts events numerically, and exposes the frozen
P13-01 plus P13-02 failure vocabulary.

No caller invokes this function yet. Loading, validation staging, URL/state,
event controls, rendering, and production availability remain P13-04/P13-05.

## Shared synthetic parity subject

`tests/fixtures/melee/multi_event_matchup_parity.json` is generated from the
accepted Python contract and contains:

- two distinct compatible Modern events plus one byte-equivalent duplicate;
- different event presentation orders and a canonical union containing two
  Beta subtypes and `unknown`;
- the exact versioned Python result, including counts, rates, Wilson intervals,
  sample warnings, contributor IDs, exclusions, provenance, and order; and
- twenty-two named incompatible mutations, one for every frozen P13-01 and
  P13-02 failure code.

The focused Python test proves the committed fixture still belongs to the
accepted Python implementation. The Node test consumes that same file and
requires an exact deep match for the success result and every rejection code.
