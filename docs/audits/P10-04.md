## Primary resource gate

`schemas/melee-minimized-resource.schema.json` freezes minimized resource
document version `1.0.0` for all four v3 resource families:

| Resource | Required persisted shape |
| --- | --- |
| Tournament | schema/type, approved tournament metadata, and completed rounds |
| Standings | schema/type, page total, approved standing rows, and decklist references |
| Matches | schema/type, page total, approved matches, and one or two competitors |
| Decklist | schema/type and exactly one approved decklist with card rows |

Every object rejects additional properties. Source event and round IDs,
decklist IDs and URLs, event-scoped HMAC references, positive numeric values,
and non-empty retained text use explicit constraints. The minimizer validates
the constructed document before serialization can return bytes to the client;
the v3 parser validates again before semantic conversion. Resume, assembly,
and retention inherit these two gates through the existing client and parser
entry points.

The Schema is intentionally not added to `schemas/manifest.json`: that
manifest maps committed public output documents, while minimized v3 resources
are internal collection artifacts and no production v3 snapshot is committed.
The repository Schema loader still validates the Schema itself.

## Supplemental prohibited-key scan

The recursive scan compares JSON object keys against the exact unused source
identity, account, profile, preference, linkage, and deck metadata keys found
by P10-01 and excluded by P10-03. It receives only one decoded minimized v3
resource after the caller has selected that contract.

It does not inspect string values, so a display name or card name that happens
to equal a prohibited source key is not rejected. It also does not scan raw
source responses, the repository, documentation, tests, or legacy v1/v2
snapshots. This avoids treating a broad zero-result text search as a privacy
guarantee. The strict Schema remains the primary allowlist; the scan is a
second safeguard if a later Schema change accidentally approves a known bad
key.
