## Controlled refresh

The new explicit `refresh-event` command is separate from scheduled collection.
For one requested official URL it:

1. applies the same format authorization, download, retry, parser, and semantic
   validation used by the hardened fetch path;
2. requires a playoff event and a numeric event ID;
3. locates exactly one existing archive with that event ID;
4. verifies the requested format, player identity set, and player-to-final-rank
   mapping against the retained archive;
5. atomically replaces the archive through a same-directory temporary file.

A failed validation or identity check preserves the original bytes. The command
does not edit `fetched.txt`, and it is not called by the production workflow.
