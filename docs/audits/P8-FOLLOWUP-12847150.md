## Purpose and boundary

This follow-up investigates why retained MTGO event `12847150` has complete
decklists and final placements but no Swiss scores, although the official page
is complete now.

This task changes documentation only. It does not change the fetcher,
normalizer, statistics generator, production workflow, retained event data, or
published statistics. It does not authorize a production refresh or remote
publication.

Official pages inspected:

- [Modern Challenge 64 — event 12847150](https://www.mtgo.com/decklist/modern-challenge-64-2026-07-1312847150)
- [Pioneer Challenge 32 — event 12844304](https://www.mtgo.com/decklist/pioneer-challenge-32-2026-06-1212844304)

## Executive finding

Event `12847150` was accepted while the source was not yet semantically
complete. The historical fetch gate required a non-empty decklist collection
but did not require standings, Swiss ranks, or Swiss scores. The fetch then
saved the event and added its URL to `fetched.txt`; later scheduled runs skipped
the URL permanently.

The current retry/defer policy does not close this gap. It activates only after
`is_event_data_complete()` rejects an event, and that predicate still accepts a
non-empty decklist collection with missing standings.

This is not an isolated retained-data defect. A repository-wide scan found the
same all-player Swiss-field omission in Pioneer event `12844304`.

## Evidence classification

### Proven facts

1. `data/modern/Modern_Challenge_64_12847150.json` contains:
   - event ID `12847150`;
   - player count `66`;
   - 32 published player/deck records;
   - final ranks 1 through 32;
   - zero populated `swiss_score`, `swiss_rank`, or `swiss_wins` values.
2. The file was first added by production commit
   `6250e346015e3beef03c22dd13e475872efc00a2` on 2026-07-13. Its Swiss fields
   were already absent in that first retained version.
3. The same commit added
   `/decklist/modern-challenge-64-2026-07-1312847150` to `fetched.txt`.
4. The fetch implementation at that commit considered an event complete when
   `event_id`, `description`, `player_count`, and a non-empty `decklists`
   collection were present. It did not require `standings`.
5. The current implementation retains that same semantic completeness rule.
   A raw probe with decklists and final ranks but an empty standings collection
   is accepted.
6. The current official event page parses as 32 decklists, 32 standings, 32
   final ranks, and 32 Swiss scores. Its player IDs and final ranks match the
   retained event.
7. Across 671 retained MTGO event files, exactly two have missing Swiss score
   and rank values for every published deck:

   | Event | Format | Published decks | Missing scores | Missing ranks |
   | --- | --- | ---: | ---: | ---: |
   | `12847150` | Modern | 32 | 32 | 32 |
   | `12844304` | Pioneer | 32 | 32 | 32 |

   All 671 retained events have final ranks for every published deck.
8. The current official page for Pioneer event `12844304` also parses with 32
   standings and 32 Swiss scores.
9. `fetch-events` has no explicit single-event refresh or force option. The
   similarly named `--force` option belongs only to Videre match fetching.
10. Production-candidate validation accepts an event document when its top
    level is valid and `players` is non-empty. It does not validate per-player
    Swiss evidence.
11. The statistics generator converts a missing Swiss score to zero rather
    than failing or marking the event unsupported.

### High-confidence inference

The official page was most likely in an intermediate publication state when
the production run first fetched it: decklists and final placements were
available, but standings were not yet available or usable. The weak semantic
gate accepted that state, and the fetched ledger prevented later healing.

This classification is supported by:

- the defect being present in the first retained revision;
- the retained player IDs and final ranks matching the complete current page;
- the same failure shape appearing in a second event;
- the fetcher's demonstrated acceptance of missing standings.

### Not provable from retained evidence

The repository did not retain the original 2026-07-13 HTML or embedded raw
payload. Therefore the audit cannot prove whether the historical standings
collection was absent, empty, or present with unusable identifiers. This
uncertainty does not change the identified control failure: every such shape
should have been rejected before storage and ledger admission.

## Causal chain

1. The event page exposed enough data to produce non-empty decklists.
2. `is_event_data_complete()` accepted the payload without standings.
3. Normalization emitted `null` Swiss fields.
4. The normalized event was saved.
5. The event URL was added to `fetched.txt`.
6. Subsequent scheduled runs skipped it.
7. Candidate validation did not reject the null Swiss fields.
8. Statistics converted those nulls to zero.

The current within-run retry and two-day cross-run defer policy sits between
steps 1 and 2, but it is unreachable for this failure shape because step 2
incorrectly reports success.

## Product impact

For event `12847150`, deck count and final-placement-based Top 8 count remain
available. Swiss-score-dependent outputs are wrong:

- all 32 published decks contribute zero points;
- none qualifies as high score in retained statistics;
- archetype and subtype average-points values are depressed.

The current official score distribution is:

| Swiss score | Decks |
| ---: | ---: |
| 18 | 4 |
| 15 | 10 |
| 12 | 13 |
| 9 | 5 |

For 66 players, the current helper derives seven rounds and a 12-point
high-score threshold. Correct source evidence therefore adds 27 high-score
decks for this event. The retained Modern one-week output for
2026-07-13 through 2026-07-19 reports 330 high-score decks, so regeneration
from repaired source data is expected to report 357, with total deck and Top 8
counts unchanged. Exact archetype and subtype changes must come from a
deterministic regeneration rather than hand calculation.

Pioneer event `12844304` is not currently part of an enabled Pioneer product,
but it must be repaired before Pioneer statistics are enabled.

## Recommended remediation sequence

The correction should be split into two focused tasks so the guard exists
before generated data is replaced.

### Task A — semantic completeness guard

Recommended ID: `P8-HOTFIX-MTGO-EVENT-COMPLETENESS`

1. Extend raw event completeness validation to require:
   - non-empty, unique decklist player IDs;
   - non-empty standings;
   - exactly one matching standing for each published deck;
   - parseable, non-negative Swiss rank and score for every published deck;
   - non-empty, unique final-rank IDs and exactly one final rank per published
     deck for the supported playoff event archives.
2. Treat missing or temporarily mismatched required records as
   `MTGOIncompleteEventError`:
   - use the existing bounded within-run retries;
   - defer within the existing two-day publication grace period;
   - do not save the event and do not mark the ledger;
   - fail outside the grace period with field-level diagnostics.
3. Treat structurally impossible states, such as duplicate IDs, as parser or
   contract failures rather than silently waiting.
4. Strengthen normalized-event and production-candidate validation so a new or
   modified retained player cannot have null Swiss score, Swiss rank, or final
   rank.

The local implementation proved that immediately enabling fail-closed
statistical consumption would make the committed Modern baseline and Pickup
rebuild fail on known event `12847150` before Task B is authorized to repair
it. Task A therefore establishes the admission and candidate-publication
barriers without changing current generated statistics.

Required regression cases:

- decklists and final ranks present, standings absent;
- one deck player missing from standings;
- one standing with missing or invalid score/rank;
- duplicate deck, standing, or final-rank IDs;
- a complete event saves and is ledgered exactly once;
- incomplete events are retried/deferred and produce neither file nor ledger
  entry;
- candidate validation rejects normalized null Swiss fields;

### Task B — controlled refresh and regeneration

Recommended ID: `P8-REPAIR-MTGO-EVENTS-12847150-12844304`

1. Add or use an explicit owner-authorized single-event refresh path.
2. Fetch each official page into a temporary file.
3. Apply the Task A semantic validator before any replacement.
4. Verify event ID, format, published player IDs, and final ranks against the
   retained file; require an explicit diagnostic for any difference.
5. Atomically replace the entire generated event document. Do not hand-edit
   Swiss fields and do not delete ledger entries as the repair mechanism.
6. Regenerate all affected Modern derived outputs and reports from source
   data. Retain Pioneer as a corrected archive until its product is enabled.
7. Audit every retained event against the normalized semantic contract and
   require zero remaining exceptions.
8. Activate fail-closed statistical consumption so missing Swiss evidence can
   no longer be coerced to zero.
9. Run production-candidate validation and focused regression checks, then
   review the generated diff before publication.

Expected Modern repair invariants:

- event deck count remains 32;
- event final ranks remain 1 through 32;
- affected period total deck count remains unchanged;
- affected period total Top 8 count remains unchanged;
- affected period high-score count increases by 27;
- no retained MTGO event has a missing Swiss score or rank after both repairs.

## Scheduling recommendation

Perform Task A and Task B before P8-05. P8-05 could technically consume the
currently intact final ranks, but starting new backend products on a known
invalid source baseline would make later P8-06 completeness work and P8-07
real-data validation harder to trust.
