## Problem

P13-03 added the accepted pure browser aggregator, but the Tabletop controller
still loaded only one matchup document. The reserved `events` URL state was not
read or written, browser history could not restore a selected set, and a
background refresh could not prove that every selected event was compatible
before committing refreshed documents.

Using the first event's hierarchy as the combined order would also be unsafe.
Single-event hierarchy rows are presentation-ranked and can differ between
events, while the multi-event result requires one deterministic stable-identity
order.

## Solution

The Tabletop controller now parses positive numeric event IDs, sorts and
deduplicates them, admits the complete requested set through the active event
catalog, and falls back to one deterministic active event when the URL contains
a malformed, stale, or unavailable member. A multi-event request loads every
selected `meta.json` and `matchup.json`, builds the observed identity union in
the complete format identity order, and invokes the accepted P13-03
`buildMultiEventMatchupContract` function only after all inputs are available.

The background-refresh path stages the catalog, active-event overview and
quality documents, and every selected metadata and matchup document in one
transaction. It re-runs complete-set compatibility before returning a commit
handle. A failed download or compatibility check therefore cannot replace any
member of the last complete cached subject.

The Tabletop matchup URL now owns
`events=<sorted,unique,event_ids>`. User selection changes create history
entries; initialization normalization and invalid-input repair replace the
current entry. Reload and `popstate` restore the admitted set without creating
another history entry. The active `event` remains the deterministic focus and
single-event Overview identity.

DEC-061 behavior remains unchanged: a second event forces `all_constructed`,
and returning to one event restores its remembered scope only when that event
still declares it. Overview continues to load and render one active event. A
temporary switch to Overview does not merge overview values or erase the valid
matchup selection retained in the same browser session.
