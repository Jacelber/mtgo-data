## Implemented result

- Each source client keeps successful JSON separately from foreground and
  background-refresh requests. Failed or timed-out requests are evicted, while
  concurrent callers for the same URL share one request. Session success caches
  use least-recently-used eviction with a 24-entry and 16-MiB limit per source;
  the catalog uses a smaller dedicated boundary.
- Foreground requests time out after 30 seconds and background refreshes after
  15 seconds. JSON is read and validated before it enters the cache. Grouped
  refreshes stage all required documents and commit them only as one complete
  unit, so a partial failure cannot mix old and new view data.
- Initial routes render text-first structural placeholders without fake values.
  Deferred failures appear beside their originating row, card, or panel while
  readable content stays in place. Retry is explicit, remains foreground-only,
  starts a new request, and restores useful focus after success.
- A visible tab checks the current view only after five minutes. Unchanged data
  is accepted silently; changed data waits behind an explicit Apply action;
  refresh failure retains the old view and offers retry. Returning online only
  announces availability and never launches a request by itself. These states
  remain outside the shareable URL contract.
- Pickup now has separate reusable index and selected-document loaders. This is
  only a loading boundary for the future Landing consumer: no Landing producer,
  Landing UI, product migration, or Pickup data was added.
- Card frames reserve the 63:88 ratio. Near-viewport image work begins within
  400 pixels and allows at most four concurrent third-party requests. Failure
  remains a readable placeholder with one explicit retry and cannot block deck
  content.
- On touch-first devices, the first card-name tap opens a full-screen preview.
  The close button, backdrop, Escape, and browser Back dismiss it with focus and
  scroll restoration; a labelled button opens Scryfall in a new tab. Desktop
  hover preview and direct card-name click remain unchanged.
- The two new interaction responsibilities are isolated in focused classic
  scripts, and every maintained application file remains below the existing
  25-KiB ceiling without a framework or build step.
