# P11-10 — Phase 8 production-resource validation

## Purpose

Make the existing read-only repository validator protect the current published
Phase 8 front-end boundary before the browser baseline needs to discover a
missing file or JavaScript syntax error at runtime.

## Scope

The task adds no production feature and changes no HTML, CSS, browser
JavaScript, generated data, statistical calculation, Schema, public path, or
protected `434455` byte. It changes only the repository validator, its unit
tests, and the static CI runtime needed to run a deterministic JavaScript
syntax check.

## Protected production boundary

The validator now requires both production entries and their exact current
local resource order:

| Entry | Required Phase 8 controllers |
| --- | --- |
| `index.html` | `mtgo-controller.js` |
| `melee/index.html` | `mtgo-controller.js`, then `tabletop-controller.js` |

It also requires the two shared Phase 8 stylesheets and all six Phase 8 runtime,
translation, model, controller, and application modules to remain tracked
regular files. The syntax check covers those six modules plus the three
retained legacy browser files. Node.js 24 is pinned in the static-validation
job before `validate_repository.py` runs.

## Invalidation map

| Protected contract | Consumers inspected |
| --- | --- |
| Production entry references | `index.html`, `melee/index.html`, Phase 8 assets, entry-contract tests |
| Repository validation result | `validate_repository.py`, validator tests, CI workflow, CI workflow tests |
| JavaScript parser runtime | local Node.js 24, static-validation Node.js setup |
