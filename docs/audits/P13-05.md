## Problem

P13-01 through P13-03 produced and reconciled the admitted in-memory
multi-event matchup result, and P13-04 loaded that complete result while
preserving canonical URL and single-event Overview state. The Tabletop page
still replaced the result with a pending placeholder, so no user could inspect
the combined matrix, its included events, or its sample and warning state.

## Solution

The Tabletop consumer now adapts the admitted `multiEventMatchup` result to the
existing hierarchical matrix renderer. It does not recalculate counts or load
another document. The combined view displays the sorted event names and Melee
IDs, included-event count, valid-match sample, raw-count aggregation note,
shared low-sample legend, and the existing cell W-L-D, literal rate, and 95%
Wilson interval presentation.

The existing multi-event scope notice remains visible and
`all_constructed` remains locked by P13-04. The combined view omits the
Tabletop mainstream projection because that control depends on per-event
metagame share and no Overview metric is aggregated. Switching to Overview
continues to show only the active single event.

Production integration remains dormant. The active public catalog still has
one legacy event and cannot admit a multi-event result, so no public second
event or multi-event selection is enabled by this code.
