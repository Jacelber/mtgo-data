## Purpose

Convert the owner-accepted P8-07 real-data prototype into a build-free,
modular production candidate. Keep the deployed MTGO page unchanged as the
regression oracle and rollback baseline. Production entry-point work belongs
to P8-09 and P8-10.

## Accepted behavior inventory

The candidate must retain these P8-07 behaviors:

- format-first navigation driven by `stats/catalog.json`;
- disabled unavailable products and format-preserving product selection;
- Chinese-first labels and the approved product names;
- MTGO share statistics, hierarchical subtype rows, sortable metrics,
  completeness, two interactive share charts, and subtype deck details;
- literal MTGO matchup records, real diagonal cells, independent row and column
  subtype expansion, low-sample warnings, gradients, and record hover/focus;
- weekly MTGO Top 8 event columns, immutable weekly bases, exact-deck details,
  deviation, and comparison decks;
- Tabletop event overview and matchup modes, scope selection, event quality,
  disqualification handling, subtype detail, and MTGO comparison provenance;
- Weekly Pickup browsing and card-image previews;
- desktop and narrow-screen behavior accepted during P8-07 review.

## Module boundary

The production candidate uses these responsibilities:

- `assets/js/phase8/runtime.js`: public-path admission, JSON fetching, and
  independent scoped caches;
- `assets/js/phase8/mtgo-controller.js`: MTGO-only document discovery and
  loading;
- `assets/js/phase8/tabletop-controller.js`: Tabletop-only event discovery and
  loading, with an explicit MTGO comparison dependency rather than shared
  mutable state;
- `assets/js/phase8/matchup-model.js`: source-neutral hierarchical literal
  matchup aggregation;
- `assets/js/phase8/app.js`: accepted shell, renderers, state transitions, and
  interactions.

The MTGO and Tabletop controllers cannot fetch each other's product trees. The
only cross-source operation is the documented Tabletop deck-detail comparison,
which calls the MTGO controller explicitly and labels the source in the UI.

## Implementation result

The accepted P8-07 assets now live under production-candidate asset paths. Both
the retained P8-07 review entry and the new P8-08 candidate load the same
ordered modules. The old deployed entry and its Phase 4 assets have no diff.

The runtime creates one cache per admitted client. The catalog client admits
only `stats/catalog.json`; the MTGO controller admits only
`stats/<format>/mtgo/**`; the Tabletop controller admits only
`stats/<format>/melee/**`. Tabletop deck detail obtains its explicitly labeled
MTGO four-week comparison through the MTGO controller rather than widening the
Tabletop path boundary.

P8-02's reusable base stylesheet, P8-07's accepted visual additions, the
hierarchical literal matchup model, and the accepted application behavior were
relocated without a build step. The older P8-02 and P8-07 review URLs were
updated to consume the relocated assets and remain functional.
