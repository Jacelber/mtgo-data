## Problem

P13-01 rejects selected events whose taxonomy versions or digests differ, and
P13-02 reconciles each event against its catalog compatibility block. Those
checks prove cohort equality, but they do not prove that an equal cohort uses
the current approved format taxonomy. Two events rebuilt under the same stale
classifier can therefore satisfy the accepted equality checks.

## Authorized solution

Advance only the future Tabletop event catalog to Schema `1.2.0` and require a
versioned top-level `active_taxonomy` identity. The maintained publisher derives
that identity from the same current taxonomy input used to rebuild the event.
The Python and browser admission wrappers support `1.2.0` for multi-event use
and require every admitted event's taxonomy version and digest to equal the
catalog-declared active identity.

Catalog `1.0.0` remains valid for existing single-event discovery. Catalog
`1.1.0` remains Schema-valid historical evidence but is not multi-event
eligible after this migration. The pure P13-01 raw-count calculation remains
unchanged.

1. a catalog with a missing or malformed active taxonomy fails closed;
2. two mutually equal stale events fail against a different active taxonomy;
3. two events matching the active taxonomy produce the versioned result;
4. Python and JavaScript preserve exact success and rejection parity;
5. catalog `1.0.0` stays Schema-valid for single-event discovery while catalog
   `1.1.0` is no longer multi-event eligible;

   current Modern taxonomy without retaining or publishing event `437444`.

## Implementation result

The future catalog producer now emits Schema `1.2.0` with a required
`active_taxonomy` version `1.0.0` block. The Python and JavaScript wrappers
support only catalog `1.2.0` for multi-event admission, retain pairwise taxonomy
checks, and then require each reconciled event taxonomy to equal the active
identity. The result compatibility block records the active-taxonomy Schema
version. Stable `missing_active_taxonomy` and `active_taxonomy_mismatch` errors
are shared across both runtimes.

Catalog `1.0.0` remains valid for existing single-event discovery. Catalog
`1.1.0` with its compatibility evidence remains Schema-valid historical input
but is rejected for multi-event use. No generated public JSON was changed.
