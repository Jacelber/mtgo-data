# 环境、候选、交付与恢复

任务授权和人工验收只依 [GOVERNANCE](GOVERNANCE.md)，必要结果与证明只依
[QUALITY](QUALITY.md)。技术入口为 `python tools/project.py --help`，子命令不是审批阶段。

## 环境与候选

使用隔离分支及项目声明依赖；文档工作不安装浏览器或全部开发环境。
先定位已有输入、候选和结论；相关对象不变则复用，必要时只更新受影响派生内容。
生成、测试和预览环境不持有归档写入凭据。独立可信上传器只处理数据包，不执行候选代码。

完整候选包含实际部署所需页面、脚本、样式、批准公开数据／目录、本地资源及部署文件。
公开打包使用明确选择，不包含整个仓库、私有输入、凭据、缓存和旧工具。
外部图片与 API 不受完整包保障，不借归档扩大抓取或本地化范围。
Owner 可直接审阅安全本地环境中的同一确定候选，无须先上传再下载。
跨环境取用或本地副本不可用时从私有归档获取；活动审阅、交付和恢复不清理唯一副本。

公开仓库的 Actions 附件不视为私有存储。云端未发布候选交接使用公钥加密的临时附件，
生成作业仅读取 `ARCHIVE_HANDOFF_CERT`；专用解密钥匙 `ARCHIVE_HANDOFF_KEY` 仅交给
`product-archive` 环境的可信上传器。上传器解密并核对原包后入库，不执行候选代码。
此钥匙不授予 GitHub 写权限，也不用于长期恢复包；长期包直接由私有归档保护。
钥匙更换前处理仍在交接的候选；归档故障期间保全活动候选，不能等待唯一临时附件过期。
本地 `seal` 使用已有 OpenSSL；不在 PATH 时用 `--openssl` 指定程序路径，不要求重装运行环境。

变化形成可区分的新候选，未受影响的验收与验证继续有效。
发布不暗中重新抓取、分类、计算或生成。内容转换尽量前移，无法前移则只补新增差异证明。
整站包须保留等待期间其它任务已交付的更新；无关计算可复用，过期组合不能覆盖新产品。

MTGO 日常更新把已验证输出的实际变化交给提交作业，不再因主分支变化重启采集和生成。
无关修改直接保留；相关输入变化列出具体路径，输出冲突保留原候选，由 Codex 聚焦处理。
提交或查询失败时续作失败的提交作业，复用该运行已有候选；没有内容变化不制造证据空提交。
Actions 临时附件不是长期保障，活动工作不得任由唯一候选过期；需要较长等待时先保全原成果。

## GitHub 私有归档

`Jacelber/mtgo-data-releases` 的 Release assets 保存不可变完整包及最小 manifest。
既有周维护所需的私有业务审阅材料单独保存为 `weekly-readiness-<run>-<digest>`，
不进入部署包、恢复版本或写入控制状态，也不扩成任务日志库。公开 Actions 只传加密附件；
可信通知作业解密、保存并取回核对。Codex 按工作流摘要中的私有位置取用，业务审阅结束后
可随该维护任务清理对应材料；活动材料不清理，不新增定时任务或 Owner 填报。
记录包标识、目标、校验值和现有来源／验证引用；不复制全量日志、Owner 对话或 PR 父链。
校验值只证明完整性，不证明业务正确或赋予发布权。拒绝损坏、越界路径、链接和特殊文件，
展开至新的独立目录，不执行归档旧脚本。正式发布前完成云端保存与恢复准备，失败只暂停依赖写入。

| 对象 | 保留 |
| --- | --- |
| 当前实际线上完整包 | 在任期间固定保留 |
| 最近仍适用的恢复前版 | 被新适用前版替换前固定保留，不看年龄 |
| 其它正式发布包 | 实际发布起 30 天 |
| 未发布或失败候选 | 活动期间保留，结束后 7 天 |

活动验收、故障、恢复引用暂不清理；明确撤回／删除要求优先。
保留与恢复资格分开，错误包可用于诊断而不可恢复。普通获准收尾可清理明确到期对象，
不增加定时任务。新发布前确认新包完整及本次依赖前版可定位取用，复用有效完整性结论。
`tools/archive_product.py finish` 记录候选不再参与活动审阅／诊断；`prune` 默认只列出到期对象，
范围内清理可用 `prune --execute`。清理先以同一条件更新排除新写入，固定引用优先；
删除结果未知时保留状态，查询后续作，不把失败删除冒称已释放空间。
首次基线来自实际部署产物，不从当前源码重新生成冒充历史版本。
没有可恢复旧版时，任务计划明确首次限制与失败处置；已知无关 P14 缺陷不要求清零，
也不能将无法完成当前恢复目标的包标为适用。

## 发布与实际事实

所有受支持写入采用同一目标协调入口。私有 `state/pages.json` 只记录实际部署、产品确认、
适用前版、未结束写入和恢复意图，不是授权台账。准备时记录实际部署操作基准，
取得写入机会时复核指令、候选组合、实际对象及前版。操作 ID 区分 A→B→A，过期请求不能复活。
保护从有效性判断持续至远端副作用可判定，不先放锁再发布。

平台完成和产品确认分别记录。B 已实际部署但确认失败时记 B 的事实，保留仍适用 A；
不等产品成功才承认版本变化，不把 B 自动升为可用前版。实际对象未知时保留未知。
必要确认：实际操作完成且对象正确、受影响入口／环境相关资源可用、公开与组合范围正确。
必要时使用最小非敏感版本标识，不要求恢复包源码 SHA 等于当前 master。
复用未受环境影响的分类、计算和页面证明。

## 从失败处续作与取消

区分产品失败、执行失败、未发生、已发生和未知；GitHub 查询故障只续查。
历史红色不改写，恢复记录新事实。请求超时先查询实际操作；暂未查到不证明未发生。
只有确认原操作不会再产生副作用，或同一操作确实可安全重试时，才重试写入。
保留操作标识，不制造新提交取绿灯。无依据时不盲试，也不建立无限后台轮询。

Owner 暂停／取消或目标变化时停止相应新动作，在现有授权内处理待执行远端操作。
本地停止不等于远端已停；不能取消或确认时说明剩余影响。已完成写入不因取消自动取得回滚权。
当前入口允许安全重试；切换前旧写入运行仅通过当前入口读取有效成果，不重跑旧控制代码。
有写权限者仍可能从平台界面重跑历史工作流，此属支持入口外能力；修改 YAML 不等于消除它。

## Owner 决定回滚，工具执行恢复

只有 Owner 明确下达回滚指令才恢复；发现故障、检查失败或 CI 红色均不自动触发。
Codex 不判断错误是否足够严重来取得回滚权，也不要求先复现故障、标记产品失败、
证明旧版能消除故障或取得新的产品测试绿灯，才执行 Owner 已作出的决定。

默认目标是本次发布前实际在线且仍适用的完整前版；整站包同时撤回其中两个产品的本次更新。
执行仅核对具体版本、归档可取用与完整、当前线上及未结束写入。若已出现后续交付、
目标包不可用或实际写入不明，如实说明具体执行障碍，不暗中选择更早版本或扩大撤回范围。
收到指令即开始执行，不重复申请普通恢复动作许可；下载、部署和处理未结束写入仍需实际时间。

## 回滚附带暂停自动发布

登记 Owner 回滚请求时，同时暂停该目标的自动发布；即使恢复暂未完成，暂停也不因运行结束而消失。
暂停只限制无人值守任务写入线上，采集、候选准备、诊断和已授权开发继续。状态由现有控制记录
`automatic_publication_pause` 表达，可通过统一 `status` 入口读取，不增加后台监控或审批台账。

暂停无自动到期时间；恢复完成、合并、测试通过、撤销恢复意图或单次发布修复版都不解除。
Owner 明确说“恢复自动发布”，或先前明确授权“完成约定修复后恢复自动发布”且条件已完成时，
Codex 使用 `project.py enable-automatic --recovery <对应恢复操作> --reason <指令或提前授权上下文>`
解除同一次暂停，不再重复询问。不能凭普通修复授权推断获得解除授权。解除本身不自动发出一次发布，
后续定时任务按正常流程执行；Owner 同时要求立即发布时按该指令连续完成。

已授权的单次任务发布可以在暂停期间执行，但不隐含恢复自动发布。无人值守调用须标记 `--automatic`，
不得通过改称手工任务绕过暂停；云端发布入口默认按自动调用处理。入口在排队前、取得写入机会和真正发送前
核对暂停及恢复冲突，已发出的操作继续查明或取消，不能把设置暂停冒称远端已经停止。

## 恢复执行与未确认状态

先确认目标包，再登记恢复意图，之后申请执行机会。登记与普通写入争用同一控制记录；
等待中的有效恢复使冲突普通请求失效。平台取消／替换队列不删除恢复意图，当前有效任务可续作。
恢复完成、明确撤销或确认失效后解除意图，不能遗留永久阻断。

处理冲突待执行请求并查明已发写入，取消请求不等于远端已停止。未知写入保留控制状态，不竞跑。
取得独占机会后复核实际部署操作与恢复目标，只部署所选包并确认该版本实际提供服务。
传输／确认失败从失败处继续，不擅自换更早版本。

确认部分或混合服务时如实记受损范围和操作，先处理未结束写入；不能冒称完整 B 已上线
推断允许回滚。已有 Owner 指令仍由当前执行入口处理；无法识别对象或排除冲突时说明执行障碍。
归档或平台故障保留实际事实并修复能力，不清空线上、不以本地副本冒称恢复。
服务恢复后同一交付必要源代码修复继续；恢复旧版不等于新功能完成。按任务终点结束。
