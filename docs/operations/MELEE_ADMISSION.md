# Melee 赛事资格与业务输入

本文件定义赛事含义，授权统一依 [GOVERNANCE](../GOVERNANCE.md)。资格、采集、候选、
验收和发布是结果依赖，不是逐阶段审批；完整计划获准后推进至约定验收点。
仅给赛事链接不能推断允许采集或公开，不自动发现其它赛事。

## 身份、资格和注册

使用明确的 `https://melee.gg/Tournament/View/<event_id>` 主赛事。
依 [PROJECT_SCOPE](../PROJECT_SCOPE.md) 确认批准类别、已完成、非团体、受支持赛制、
名称、日期、主办方及来源。依据赛事页与主办方指南／日程确认：

- `mixed`、`constructed_day2` 或 `constructed_single_stage`；
- 每轮阶段、实际赛制、Swiss／淘汰性质、统计适用性；
- 晋级／切分规则、Top 8 lock 及特殊 `Qualified` 含义；
- 牌表、排名、对局、结果覆盖和需配置覆盖的具体例外。

默认 `all_constructed_swiss`，淘汰赛仅保留上下文，不进入主要胜率和对局。
未知轮次标明并排除，重要边界不能证明时不将赛事标为完整可信。
证据不足时可依已授权范围临时采集，临时成功不改变保留或公开范围。

`configs/melee_events.yaml` 注册 ID、URL、赛制、结构、启用／核实状态、来源证据、
阶段映射、晋级、特殊处理与请求计划。采集前拒绝未列出、禁用、未核实 ID。
注册不等于已公开。数据字段与保留边界见 [DATA_ARCHITECTURE](../DATA_ARCHITECTURE.md)。
完整输入已有则复用，恢复 checkpoint 不回退为新采集；明确空牌表与请求失败分开。

## 候选与审阅

候选保留已有赛事及未批准改变的默认选择。同赛制多赛事选择须 taxonomy、scope 和
质量含义一致，只用批准的 `all_constructed` 从 W-L-D 合计重算，不平均事件百分比。
不静默丢弃不兼容选中项或降级 taxonomy；单赛事独立上线须符合批准范围。

动态核对参与者、排名、牌表、轮次、对局和 Constructed 机会数，不冻结历史总数。
检查未知轮次／结果、bye、no-show、ID、awarded win、DQ、淘汰赛、Unknown、冲突和无效牌表。
不可用牌表单列；临时接受非阻断 Unknown 群体是业务决定，记录对应对象和数量。
公开产品使用事件域内 derived participant_id；受允许源 ID 留在既定 Git 输入边界。

分类或语义改变按当前计划和统一决策边界处理，不因进入修复阶段自动另开任务，
也不借修复改变已确认含义。必要更新派生结果，不重抓输入。
按 [QUALITY](../QUALITY.md) 取得受影响 R1/R2/R3 证明，实际候选与验收一致。

## 周维护补充与交付

Owner 指定赛事在来源完整保留、分类可复现、可用牌表可审阅、无妨碍审阅工程问题时，
可在公开前后参与同赛制周审阅。记录周、赛制、赛事、来源、对象位置、分类主体、
可用／Unknown／不可用数量；不写成 STATUS 授权或 MTGO 完成记录。
所有可用分类供完整审阅，来源、统计、公开及完成状态与 MTGO 分离。

交付走 [DELIVERY](../DELIVERY.md)。候选分支或 merge 不等于线上。
实际确认选中赛事、批准组合、资源及必要交互；复用有效机制和分类结论。
不通过改写原始输入或回退整个仓库恢复产品。
