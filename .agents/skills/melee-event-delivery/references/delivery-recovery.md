# 交付与恢复

只有本次授权包含上线且约定页面验收已成立，才对数据交付记录执行：

```powershell
python tools/weekly_maintenance.py continue-delivery --record DELIVERY_RECORD
```

这会沿记录准备资源、组包、私有归档和提交远端操作；预览对应的完整站点有效时复用。该命令不是只读查询。已有未结束操作时按 `docs/DELIVERY.md` 接续，不能另造 operation。

提交／合并前核对最新主分支及线上组合，保留并行交付；正常提交、PR、修复与合并沿用已批准计划。固定材料后不暗中重新采集、分类或重算。来源、规则或实际组合变化时保留旧记录，建立对应候选，仅补实际失效的证明和人工判断。

完成需要平台健康通过、当前 operation 与包一致、受影响线上资源匹配固定包，并实际操作事件概览、主备牌及受影响矩阵。PR 合并、工作流成功或 pending 为空单独都不足以证明交付。周报正文、选稿、展示牌和完成记录与已发布基准保持；技术绑定变化与序列化差异分别说明，不把字节差异自动当业务变化。

恢复按实际失败点处理：

| 事实 | 接续 |
| --- | --- |
| 原始输入已保存，分类／派生失败 | 复用 checkpoint 或本地 generation 记录，只修失败环节 |
| 候选登记慢 | 查阶段耗时及实际进程；修正常入口，保留原目录，不从采集重来 |
| 同周周报重绑定拒绝 | 核对被改变的具体业务字段；技术修复自主完成，新业务取舍才提问 |
| 包预算超限 | 在固定前处理受支持编码／范围；数值一致不等于元数据无需重绑定 |
| 已提交，响应超时或查询失败 | 查询原 operation；不重建包、不重新提交 |
| 线上基准变化 | 保留并行产品，形成新组合；已提交操作按实际状态处置 |

验证范围按真实风险选择，复用有效结果。发布或恢复成功后报告实际包和入口并结束；本次单赛事交付不产生整周完成记录。

开发演练只用隔离目录、保留输入和测试替身；禁止调用真实采集、归档上传或部署接口。离线预览与数据生成可真实运行，发布状态不明、并行基准变化等分支用既有恢复测试验证。
