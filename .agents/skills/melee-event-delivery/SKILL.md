# Melee 赛事交付

恢复用户指定赛事、实际授权终点、已确认决定及保留成果。从第一个实际缺口继续；仅给链接不推断采集或公开授权。完整计划获准后连续推进至约定验收点，技术修复和同一交付续作不重复请求授权。

## 执行原则

- 原始输入先保留再派生。已有完整输入直接复用；来源缺失或更新才补对应范围。Unknown、来源无牌表和请求失败分别报告。
- 规则未变走单赛事路径。共享规则改变先确定同赛制当前 Melee 与 MTGO 消费者，按依赖同步后再提供完整预览；使用现有同输入影响证明，未解释差异不能通过改 expected 消除。
- 单赛事同步保留既有周报选稿、正文、展示牌、审阅材料和完成记录；技术绑定可以更新，业务内容变化仍按用户决策边界处理。
- 预览复用正式白名单打包器及完整资源。冷启动检查牌表主备牌、单赛事矩阵；共享分类改变再检查新旧赛事组合。机器先解决缺依赖、名称、颜色、资源和包体积问题。
- 固定材料后只组包和发布。候选发生实际变化保留旧记录，复用不受影响的验证和验收；提交过的发布查询原 operation。
- 记录真实阶段耗时、已执行／复用生成步骤及实际请求数，区分工具运行、外部等待和用户审阅。沿用已有产物和进度记录，不新建审批台账。

业务含义依项目 [Melee 规范](../../../docs/operations/MELEE_ADMISSION.md)，责任与授权依 [GOVERNANCE](../../../docs/GOVERNANCE.md)，验证依 [QUALITY](../../../docs/QUALITY.md)，发布依 [DELIVERY](../../../docs/DELIVERY.md)。这些文档各自维护含义，skill 负责操作路由。工具均从实施 checkout 调用，显式指定隔离候选路径；使用任务已确认的 Python。

报告实际对象、覆盖与限制、入口及下一步。到达本次终点即结束，不自动扩展到周维护、其他赛事、监控或生产演练。
